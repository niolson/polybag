# UPS validation for UPS-only methods, with its liability notice

Status: wontfix
Category: enhancement
Created: 2026-10-01

## Parent

[address-validation-routing PRD](../PRD.md)

## What to build

The UPS API Access Agreement allows address validation only for a package intended for
UPS, and requires a liability notice wherever its results are shown. These ship together
so there is never a window in which UPS results appear without the notice.

- **UPS eligibility:** every carrier service on the method is UPS, and the method does not
  allow Amazon Buy Shipping (Amazon may sell a non-UPS label). The Client must have an
  active UPS account. A Shipment with no method is never eligible.
- **US and PR order:** FedEx when eligible, then UPS when eligible, then USPS, then Google
  — unless [06](06-ups-reliability-comparison.md) concludes otherwise.
- **Mapping:** a valid-address indicator is `verified`, per
  [03](03-deliverability-says-what-the-evidence-supports.md), unless 06 finds a
  delivery-point signal.
- **The notice** is shown with the validation result wherever its source is UPS: View
  Shipment and Manual Ship. It uses UPS's own wording from the agreement, verbatim, kept
  in one place. It is absent on every other source.

## Acceptance criteria

- [ ] Plan tests: UPS appears only for UPS-only methods with a UPS account, and never for
      mixed, Amazon-Buy-Shipping or no-method Shipments
- [ ] A UPS-settled Shipment records UPS as its source and shows the notice on View
      Shipment and in Manual Ship
- [ ] A USPS-, Google- or FedEx-settled Shipment shows no notice
- [ ] A UPS inconclusive falls through to USPS
