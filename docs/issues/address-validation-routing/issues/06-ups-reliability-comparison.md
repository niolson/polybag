## What to build

FedEx and Google were compared in production on 2026-09-30 before deciding where each
belongs in the chain (see the PRD's Further Notes). UPS has had no such run, and nobody on
the project knows how its Street Level validation behaves on real data. Putting it ahead
of USPS for UPS-only methods without that evidence could accept wrong addresses.

Run the same method against UPS's production XAV endpoint:

- The US set USPS confirmed deliverable: does UPS return a valid-address indicator for
  each, and what does it return for the inflated house numbers?
- PR, and how UPS handles secondary (apartment/suite) numbers — missing, wrong, present.
- Whether a valid indicator ever comes with a candidate that differs from the input, the
  substitution FedEx does internationally.
- Whether any part of the response is a delivery-point signal worth `yes` rather than
  `verified`.

Raw captures carry real addresses and go in `.scratch/`, not the repo. Record the summary,
the conclusions, and the resulting mapping in this file's Comments.

This is HITL: it needs production UPS credentials and a maintainer's judgement on the
result.
