# Probe Amazon listings for weights and customs fields

Status: ready-for-human
Category: research
Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

[PRD](../PRD.md), *Amazon*. Blocks `04`. Informs `05`.

## Problem

`04` depends on facts nobody has measured:

- How often a seller's listing carries `item_package_weight` and `item_weight`, in which
  units, and how often they are implausible.
- Whether an HS code or country of origin is anywhere in the listing or catalog
  attributes. The 2026-10-05 probe (`product-identifier-import/05`, `06`) looked only at
  `country_of_origin`, `part_number` and `model_number`, found no origin, and kept counts
  only. The raw responses are gone, so nothing can be re-read.
- Whether the merchant listings report is open to the app's roles. If it is, `04` can
  list every SKU without date windows.
- How date windows behave in practice: how a real account's listings spread over
  `createdDate`, and whether bulk uploads bunch them.

It needs a human because it runs against a production seller account.

## What to do

Read-only, on an OAuth Amazon connection, with a script in
`.scratch/product-catalog-sync/`. **Save every raw response there** (gitignored) so later
questions can be answered without another probe.

1. **Listings.** `searchListingsItems` with `includedData=summaries,attributes`,
   `pageSize=20`, `sortBy=createdDate`, over date windows, until a few thousand listings
   or the whole account. Record the oldest and newest `createdDate` and the largest number
   of listings created within one second.
2. **Catalog.** `searchCatalogItems` for those ASINs with
   `includedData=attributes,dimensions,identifiers,summaries,classifications`.
3. **Search both for customs fields.** Every attribute name containing `origin`,
   `country`, `tariff`, `hs`, `harmonized`, `customs`, `commodity` or `import`, with fill
   counts and sample values. Note the product types they appear on.
4. **Weights.** For each source (listing `item_package_weight`, listing `item_weight`,
   catalog `item_weight`, `item_package_weight`, `dimensions.*.weight`): fill rate, units
   seen, and the distribution in pounds. Count values over 150 lb, under 0.01 lb, and
   where listing and catalog disagree by more than a factor of two.
5. **Report.** `createReport` for `GET_MERCHANT_LISTINGS_ALL_DATA`. Record whether it is
   accepted or refused (403 means the role is missing), and if accepted, its columns and
   row count against the listings search.

## Output

A comment here with the counts, and the scratch path of the captures. Update the PRD's
*Amazon* section, `04` and, if HS codes turn up, `05`, then set `04` to `ready-for-agent`.
Nothing with real SKUs, ASINs, seller IDs or product names goes into the repo.
