# Remove Rate Comparison and Packing Validation; show Prepaid Duties only where DDP is used

Status: done

> *This was generated by AI during the reports review.*

## Problem

- **Rate Comparison** counts a saving whenever any cheaper quote was offered, whatever its
  service class or delivery date. Packers choose within a shipping method, and the cheaper
  quote is usually a slower class the method was set up to avoid. The fair comparison
  (cheapest that met the same date) needs `quoted_delivery_date`, which most quotes lack.
  What the report was reaching for is filed as [`09`](09-audit-shipping-method-choices.md).
- **Packing Validation** is three lists that share a page and nothing else, and its name is
  also the name of the scan-every-item setting (`ui-review` ST1).
- **Prepaid Duties** is an empty table on any install that doesn't ship DDP.

## Fix

1. Delete Rate Comparison, its view and its tests. Keep `rate_quotes` and
   `RateQuoteLogger`: the log is what `09` would read.
2. Delete Packing Validation. Add to the Packages list:
   - a **Weight mismatch** filter (`packages.weight_mismatch`);
   - an **Address not confirmed** filter (Shipment `deliverability` not in
     `Deliverability::confirmed()`).
   Batch failures stay where they already are: Label Batches and the Exceptions widget.
3. Prepaid Duties is reachable only when a DDP Label exists, or a Client's duties policy
   names DDP for some destination.

## Done when

The two pages are gone, the Packages filters are tested, and Prepaid Duties' access rule is
tested both ways.
