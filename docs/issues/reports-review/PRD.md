# Reports review

Status: reference

> *This was generated by AI during a review of the Reports navigation group.*

## Goal

Every report in the Reports group is useful to most installs, or appears only where it
applies. Reports that can't be made trustworthy with the data we record are removed, not
kept with caveats.

## Findings (2026-11-24, at `211d3864`)

| Report | Verdict |
|---|---|
| Volume | Keep. The rollup already holds carrier, service, location and weight the report never shows; the drill-down links filter Shipments by import date, so they never match the number clicked (`release-polish/33`) |
| Packages by User | Keep. One number per user; groups by name, so two users who share one merge; ISO week numbers with the calendar year |
| Client Billing | Keep, multi-client only. Prepaid duties are never billed |
| Prepaid Duties | Keep, but only where DDP is in use; otherwise an empty table under a paragraph about IOSS |
| Rate Comparison | Remove. "Cheapest" is the cheapest quote from any service class, so the savings are mostly Ground against Priority; only 148 of 10,007 local quotes have a delivery date to compare fairly against; automation already buys the cheapest within the allowance |
| Packing Validation | Remove. Three unrelated lists under a name that collides with the packing validation setting: weight mismatches become a Packages filter, batch failures are on Label Batches and the dashboard, unverified addresses become a Packages filter |

Missing: how quickly orders leave against `ship_by`, how carriers perform once a parcel
has left, and voided labels awaiting refund.
