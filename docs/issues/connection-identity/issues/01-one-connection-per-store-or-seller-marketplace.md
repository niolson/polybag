# One connection per Shopify store, and per Amazon seller and marketplace

Status: ready-for-agent
Category: bug
Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

None: a feature of its own, found while building `connection-onboarding/03` on
2026-10-29. Not blocked.

## Problem

Nothing stops two active connections reading the same orders. An operator created a
second Amazon connection to the same seller and marketplace, and nothing objected.

Imported Shipments are unique per connection, not per order: the key is
`(data_source_id, source_record_id)` (`shipments_data_source_record_unique`), and
`ShipmentBatchWriter` upserts on it. Two connections to the same account each import their
own copy of every order. The packing queue shows two Shipments for one order, and either
can be packed and given a Label. Once one copy ships and its tracking is confirmed, the
other connection's next import should close its copy, because the source now reports the
order closed. That limits the damage but does not prevent it: both copies are open until
then.

The same is true of two Shopify connections to one shop domain.

`import_account_key` does not help. It names the account a connection last read from, so
the connection can reset its own import cursor when its account changes. It is never
compared with another connection's.

## Desired behavior

A connection's **account identity** is what it reads orders from:

- **Shopify:** `settings.shop_domain`, compared case-insensitively.
- **Amazon:** the seller ID OAuth records (`amazon_selling_partner_id`) and
  `settings.marketplace_id`. A connection with its own refresh token records no seller ID,
  so it has no identity to compare and is not checked. In Production and Demo with the
  broker, that field is hidden (`connection-onboarding/02`).

No two **active** connections share an identity. An inactive one may, so an old
connection can be kept for history while a new one replaces it.

Where it is enforced:

- **Shopify, on create and save.** The shop domain is known on the form, so this is
  validation on `settings.shop_domain`: "Another active connection, *{name}*, already
  reads this store." Also when an inactive connection is made active.
- **Amazon, after OAuth.** With `connection-onboarding/03`, neither the seller ID nor the
  marketplace is known on create. When marketplace discovery would select a marketplace
  that another active connection already holds for this seller, it does not select it,
  and the callback's notification says which connection holds it. A seller with several
  marketplaces is offered only the ones not taken.
- **Amazon, on save.** Choosing a marketplace, or activating the connection, fails
  validation on `settings.marketplace_id` when another active connection holds this seller
  and marketplace.
- **Amazon, on reconnect.** A connection reconnected to a different seller is checked
  against its existing marketplace the same way, by discovery.

The rule lives in one place, something like `DataSource::conflictingConnection(): ?DataSource`,
and the form, the callback and discovery all ask it.

## Notes

- One Seller Central account selling in the US and CA needs two connections, one per
  marketplace. `settings.marketplace_id` holds one value, and the order search, shipment
  confirmation, Buy Shipping and the catalog sync all read it. Two connections with the
  same seller and different marketplaces read different orders and are allowed. Supporting
  several marketplaces on one connection is a larger change and is not part of this.
- Existing duplicates are not repaired. There are no live tenants.
- A unique index cannot express this: the identity spans a JSON setting and a secret, and
  applies only to active rows. Enforce it in the application.

## Acceptance

- [ ] Creating or saving an active Shopify connection with the shop domain of another
      active one fails validation naming that connection; differing only in case still
      fails
- [ ] An inactive Shopify connection may share a shop domain; activating it fails while the
      other is active
- [ ] Discovery does not select a marketplace another active connection holds for the same
      seller, and the OAuth notification names that connection
- [ ] Saving an active Amazon connection with another's seller and marketplace fails
      validation on the marketplace
- [ ] Two Amazon connections with the same seller and different marketplaces save
- [ ] An Amazon connection with its own refresh token and no seller ID is not checked
