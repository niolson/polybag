# Import Amazon address classification and persist explicit residential data

Status: needs-triage
Category: bug
Repo: `polybag`

## Parent

[Rate accuracy background](../PRD.md).

## Problem and evidence

The Orders v2026-01-01 API used by `AmazonSource` exposes
`recipient.deliveryAddress.addressType`: `RESIDENTIAL`, `COMMERCIAL`, or
`PICKUP_POINT`. `AmazonSource::mapOrderToShipment()` does not map that field.
`ShipmentRowPreparer::prepare()` also omits `residential` from persisted attributes,
so adding the source mapping alone cannot fix the import.

New Shipments inherit the database's `residential = true` default even when Amazon
explicitly identifies a commercial address. This affects direct-account postage for
Amazon-originating Shipments as well as any app logic using the classification.
Import source and postage source remain independent concepts.

Sources:

- [Amazon Orders v2026-01-01 schema](https://raw.githubusercontent.com/amzn/selling-partner-api-models/main/models/orders-api-model/orders_2026-01-01.json)
- [Shopify MailingAddress](https://shopify.dev/docs/api/admin-graphql/latest/objects/MailingAddress)
  has no standard residential/commercial field. Company name is not a substitute.

## Acceptance criteria

- Map Amazon `RESIDENTIAL` to true and `COMMERCIAL` to false, and persist both
  through the shared import pipeline without losing false through truthiness checks.
- Treat missing, unrecognized, and `PICKUP_POINT` values explicitly; do not infer
  commercial from every value other than `RESIDENTIAL`. Preserve pickup-point
  information separately if needed by the agreed classification representation.
- Preserve the difference between a missing source field and an explicit value.
  Reimports without classification must not erase a previously known classification.
- Respect existing recipient-unavailable and historical-import preservation rules,
  client scoping, and validated classification precedence.
- Persist explicit residential input from other supported import sources when
  provided through their existing contracts; do not fabricate Shopify classification.
- Leave the unknown-address fallback to the policy agreed in issue 02. Do not
  silently migrate historical defaults into confirmed classifications.

## Verification

Extend `tests/Feature/AmazonImportExportTest.php` and
`tests/Feature/ShipmentImportServiceTest.php` with synthetic Orders API responses.
Cover residential, commercial, missing, pickup-point, and unexpected values; then
assert persisted Shipment state and effective `RateRequest` classification.
Test repeat imports with missing and changed values, validation precedence, and
recipient-unavailable/historical preservation. Retain Shopify import coverage
showing the absence of a source classification. Run affected tests with no external
API calls or real order data.
