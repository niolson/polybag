# Fill-only import fields

Status: ready-for-agent
Category: enhancement
Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

[PRD](../PRD.md), *Amazon*. No dependencies. `05` and `06` build on it.

## Problem

`ImportReferenceResolver::productIdFor()` writes every non-null imported value over the
Product. The one exception is a single-purpose flag: `_fill_missing_barcode_only`, set by
`AmazonSource`, which stops the catalog barcode replacing one already on file.

`05` and `06` need the same rule for part numbers and origins, and a second boolean per
field would not scale.

## Desired behavior

An item row may carry `_fill_only: list<string>`, naming product fields that are written
only when the Product's current value is blank. `AmazonSource` sends
`['barcode']` in place of the old flag, and the old flag is removed. A field not in the list
behaves as today.

## Acceptance criteria

- [ ] `_fill_only` naming `barcode` keeps an existing barcode and fills a blank one,
      matching today's `_fill_missing_barcode_only` tests, which move over
- [ ] `_fill_only` naming `manufacturer_part_number` keeps an existing part number and
      fills a blank one, while an unlisted field in the same row (`name`) still overwrites
- [ ] `_fill_missing_barcode_only` no longer appears in `app/` or `tests/`
