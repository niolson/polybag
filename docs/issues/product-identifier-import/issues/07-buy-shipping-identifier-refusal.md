# Amazon Buy Shipping is refused for identifiers it never sends

Status: needs-triage
Category: bug
Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

[PRD](../PRD.md). Found while investigating it; independent of the other slices.

## Problem

`ShipRequest::customsItemsMissingProductIdentifiers()` exempts a blind purchase (Shopify
Shipping) because PolyBag sends none of its own declaration. The
[`eu-product-identifiers` PRD](../../eu-product-identifiers/PRD.md) says Amazon
Buy Shipping is the same: *"Both platforms build the customs declaration from their own
order and catalog data … No adapter change."*

But a Buy Shipping offer is a quoted offer, not a blind one, so the exemption does not
reach it. `AmazonBuyShippingAdapter` sends no PolyBag customs lines. So an Amazon order
going to an EU consumer on Buy Shipping is refused when the Product has no part number, a
value the label would never carry.

Plausible from reading the code; not yet shown by a failing test. Nothing ships this way
today, since no tenant ships to EU consumers.

## To decide

- **Exempt it**, keyed on the postage source rather than on `blindOffer`, so the gate
  states what it actually means ("PolyBag declares nothing on this label").
- **Or keep it** as a deliberate data-quality nudge, and say so in the method's docblock.

Either way,
[international-customs-terms/05](../../international-customs-terms/issues/05-customs-readiness-checker.md)
moves this guard into `CustomsReadiness` "unchanged including its blind-offer gate". So
this should be decided before that issue, or it should carry the decision. The same
question applies to its new origin and HS-code blocks.
