# Suggest HS codes for Products without one

Category: enhancement

## Parent

None: a feature of its own. It started as `product-catalog-sync/05` and moved out on
2026-10-29 (see *Comments*). Not blocked. `product-catalog-sync/03` found no HS code
anywhere in Amazon's listings or catalog, so every Amazon Product needs one from elsewhere.

## Problem

International labels into the EU and GB refuse a line with no HS code
(`international-customs-terms/05`). Shopify supplies one when the merchant entered it.
Amazon supplies none as far as anyone has looked, and Database sources only when the
client's system has one. A client with hundreds of Amazon SKUs has to classify each by
hand before its first EU or GB parcel.

## Options to evaluate

- **FedEx.** Check the FedEx developer catalog for a classification or HS-lookup service
  and what an account must enable. FedEx Global Trade (whose spec is in
  `.scratch/international-customs-terms/specs/`) answers document and regulatory
  questions for a shipment; check whether it classifies.
- **UPS.** Check UPS's developer catalog for a classification (Global Trade / Landed Cost)
  API, and whether it needs a separate contract.
- **Third-party classifiers** taking a product title and description and returning an HS
  code with confidence. Cost per lookup and terms matter: product data leaves PolyBag.
- **Anything already paid for.** A client's carrier contract may include one of the above.
- **The USITC HTS REST API** (`https://hts.usitc.gov/reststop`, page 22 of the
  [HTS user guide](https://www.usitc.gov/documents/hts/hts_external_user_guide.pdf)).
  Free, no key, no documented rate limit. Two endpoints: `search?keyword=` over tariff
  line descriptions, and `exportList?from=&to=&format=JSON|CSV|XLSX` for a range of the
  schedule, in order. Each row has `htsno` (up to 10 digits), `description`, `indent`
  (depth in the tree), `units` and US import duty rates. Called on 2026-10-21. Its limits:
  - **It does not classify.** Search matches words in the legal descriptions and returns
    results in schedule order, not ranked by relevance. "lip balm" and "bluetooth
    headphones" found the right heading. "vitamin c gummies" (328 results) led with crab
    species, "stainless steel water bottle" (608) with pike and perch, and "cotton
    t-shirt" (799) with seeds. "dog collar" put the right line sixth, after live dogs and
    dog food. There is no best match to suggest.
  - **The guide is wrong about result size.** It says search returns at most 100 results.
    The searches above returned up to 799.
  - **These are US import codes (HTSUS).** Only the first 6 digits are the international
    HS code that EU and GB customs read. US export filings use Census's Schedule B, which
    mostly matches HTSUS at 10 digits but not for goods on the Census Notice to Exporters
    list.
  - **Its only error is a 500,** and the guide promises nothing about uptime.

  What it is good for: **checking an entered code** (that it exists, with its description
  shown beside it so a wrong chapter stands out), and a **code picker** on the Products
  form built from an `exportList` copy of the schedule held locally, not called on each
  keystroke. Whatever does the suggesting, this checks what is accepted and shows what it
  means.

- **Amazon's UNSPSC code**, as an input, not an answer. `product-catalog-sync/03` found the catalog's
  `unspsc_code` filled on 98% of one seller's 22,950 ASINs, and on 99–100% in every
  display group of a 5,574-ASIN sample across categories. Codes are mostly class level
  (60%) or commodity level (36%), and consistent within a product kind: men's t-shirts
  `53101600` (shirts), running shoes `53111600`. Some groceries carry only the segment.
  UNSPSC is a product taxonomy, not a tariff schedule, and has no official mapping to HS.
  A class narrows the HS chapter but not the 6-digit code (a shirt's heading depends on
  knit or woven, and its subheading on fiber), so it could seed a picker or a classifier's
  prompt. The catalog's browse-node `classifications` are another such signal.

For each: inputs (title, description, category, image?), output (6-digit HS, or a
10-digit national tariff code, and for which countries), confidence, price, and rate limits.

## Shape of a fix (to settle in triage)

A suggestion is not a declaration. Whatever the source, a suggested code should be shown
for a person to accept, never written straight into `hs_tariff_number`: a wrong code on a
customs declaration is the seller's liability. That points to a *Suggest HS code* action
on the Products page (and a bulk action under the *Incomplete Customs Data* filter from `product-catalog-sync/02`), storing the
suggestion and its source until someone accepts it.
