# Customs terms data model and forms

Status: ready-for-agent
Category: enhancement
Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

[PRD](../PRD.md), *Data model*; ADR-0008 decisions 1–3. No dependencies. `04`, `05` and
`10` build on it.

## Problem

Nothing in the schema can hold a duties policy, a seller tax registration, a recipient tax
ID or an export ITN, so no adapter can send one.

## Desired behavior

**Enums.** `DutiesTerms` (`Ddp`, `Ddu`); `TaxRegistrationRegime` (`Ioss`, `UkVat`, `Voec`,
`Arn`), each case knowing its destinations (via `AddressData::isInEuropeanUnion()` for
IOSS; GB for UK VAT, including Northern Ireland; NO; AU), its number pattern and its
low-value threshold with currency; `RecipientTaxIdType` (`Cpf`, `Cnpj`, `Pccc`, `Vat`,
`Other`) with format checks for the first three (CPF and CNPJ check digits; PCCC `P` + 12
digits).

**Client.** `clients.duties_policy` JSON, keys `EU` or ISO-3166 alpha-2 codes, values
`ddp`/`ddu`. The client form shows an EU row first, marked as required before EU labels
can be bought, with DDP recommended in its helper text, and lets an operator add country
rows below. A `client_tax_registrations` table (`client_id`, `regime`, `number`, unique on
the pair) with a repeater on the client form, numbers checked against the regime's
pattern. Factory states for each.

**Shipment.** Nullable `duties_terms`, `seller_tax_regime`, `seller_tax_number`,
`recipient_tax_id_type`, `recipient_tax_id`, `export_itn` (`X` + 14 digits). Editable on
the Shipment form under a *Customs* section, behind the existing `ShipmentPolicy::update()`
(manager and above). Shown on the Shipment view.

**Import.** The Database driver's field mapping gains all six Shipment fields, validated
as above; a value that fails is reported per row, not silently dropped. Update
`docs/data-sources/database.md`.

**PII.** `recipient_tax_id` is a national ID number. Add it to whatever
[pii-retention](../../archive/pii-retention/) purges for Shipment addresses, and to the
`customsFormData` purge list.

## Acceptance criteria

- [ ] Migrations, models, casts, factories (with states for a DDP-EU client and a client
      with an IOSS registration)
- [ ] Format checks reject a malformed IOSS, UK VAT, VOEC, ARN, CPF, CNPJ, PCCC and ITN at
      entry and at import, and accept a valid one of each
- [ ] A registration whose regime does not exist for the client is creatable; a second for
      the same regime is not
- [ ] A user below manager cannot edit the Shipment customs fields
- [ ] A Database import maps each field, and a malformed value is reported against its row
- [ ] The recipient tax ID is covered by PII retention
