# FedEx stops billing duties to the shipper on every international label

Status: ready-for-agent
Category: bug
Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

[PRD](../PRD.md). Independent of everything else here; `07` later drives the value from
resolved terms.

## Problem

`FedexAdapter::buildRateApiRequest()` and `FedexAdapter::buildCustomsClearanceDetail()`
both send `dutiesPayment.paymentType: SENDER` on every international request. Every
international FedEx label therefore bills duties and import taxes to the carrier account,
weeks after delivery, for every destination — Canada and the UK included — without anyone
having chosen DDP. UPS and USPS ship DDU, so FedEx is also the one carrier that disagrees
with the others.

## Desired behaviour

Both requests send `paymentType: RECIPIENT`, with no payor block, so every carrier ships
DDU until `04`–`08` make the term a decision. `shippingChargesPayment` (transportation)
stays `SENDER` — only duties change.

The commercial invoice gains `termsOfSale: DDU`, so the invoice says what the payment
block does.

## Acceptance criteria

- [ ] An international FedEx rate request sends `dutiesPayment.paymentType: RECIPIENT`
- [ ] An international FedEx ship request sends `RECIPIENT` with no duties payor, and
      `commercialInvoice.termsOfSale: DDU`
- [ ] Transportation is still billed `SENDER` to the resolved account
- [ ] `fedexShip.json` (the hand-written request schema) accepts the new body; the FedEx
      adapter tests that assert the old `SENDER` duties block are updated
