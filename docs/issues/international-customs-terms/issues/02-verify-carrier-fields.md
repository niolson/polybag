# Verify the carrier fields the PRD marks *verify*

Status: ready-for-human
Category: research
Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

[PRD](../PRD.md), *Carrier field mapping* and *Open questions*. `06`, `07` and `08` each
need their own carrier's answers before they are built; this can run alongside `03`.

## Problem

Several fields in the mapping are inferred from secondary sources. Building three
adapters on guesses is how `amazon-buy-shipping/10` sent an invalid purchase body for
weeks. `eu-product-identifiers/05` found the FedEx sandbox cannot buy an EU label, so
some answers need a production buy-and-void.

## What to find out

Per carrier, record the request sent and the answer received in `.scratch/international-customs-terms/`
(no account numbers or real addresses in anything committed).

**UPS (CIE sandbox, then production where CIE cannot answer)**

- DDP: does a second `ShipmentCharge` Type `02` `BillShipper` with `TermsOfShipment: DDP`
  buy? Does a rate request carrying it return the Duty and Tax Forwarding Surcharge?
- IOSS, UK VAT and VOEC through `VendorInfo` (Vendor Collect ID): the exact shape and
  type codes
- Recipient tax ID on the ship-to: field and type codes
- ITN and the `NO EEI 30.37(a)` / `30.36` exemption: which `InternationalForms` field

**FedEx (production buy-and-void where the sandbox cannot)**

- The `tins[].tinType` FedEx expects for IOSS, UK VAT, VOEC, ARN; shipper or importer side
- Recipient `tins` for CPF/CNPJ and PCCC
- `exportDetail` for an ITN and for an exemption
- Does a rate request with `dutiesPayment: SENDER` price differently from `RECIPIENT`?

**All three, from the threshold research (PRD, *Tax registration regimes*)**

- Australia: can the request mark individual items GST-paid (Australian customs' `PAID`
  exemption code, with the ARN as Vendor ID), or only send one ARN for the shipment?
  If there is no per-item mark, `05` keeps blocking AU parcels that mix an item over
  AUD 1,000 with an ARN
- Norway: confirm the VOEC number reaches the destination electronically (for USPS, in
  the ITMATT pre-advice), as Skatteetaten requires
- UK: where the seller's UK VAT number goes; no HMRC source names a customs data element

**USPS**

- IOSS: `exportersReference` or `importersReference`, and which reference type
- Does `prepayDutiesTaxesFees: true` to an "optional" country (e.g. NL) prepay, and what
  does it return for a "not available" country (e.g. PL)?
- What error comes back for a DDP-required country (e.g. DE) without the flag?
- Does USPS require the platform to present its DDP provider's terms and record
  acceptance, or does enrolment on the USPS side cover it? This decides how much of
  `08`'s acceptance UI is needed
- Ask USPS: what happens after 31 October to a DDP parcel into Germany with no IOSS number?
