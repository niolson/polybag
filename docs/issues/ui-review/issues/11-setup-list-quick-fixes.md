# Box Sizes opens on inactive packaging, Hazmat offers classes that do nothing, and "New package" bypasses packing

> *This was generated by AI during the ui-review walk-through.*

Status: done

Source: [findings](../findings.md) BX1, PR1, PK1

Page or flow: Box Sizes list; Product form; Packages list

Severity: medium

Call: before the demo

## Problem

- **BX1.** The first two pages of Box Sizes are 35 inactive USPS packages; the 13 boxes in use
  start on page three.
- **PR1.** The Product form's Hazmat select offers Dry Ice and Cremated Remains, which are
  "not yet wired to carriers" and whose Special Services are inactive, so a product marked
  dry ice ships as if it were not.
- **PK1.** The Packages list's **New package** form creates a Package with no items, box or
  Label, outside `PackageDraftWorkflow`. Decided: remove it.

## Fix

1. Box Sizes: an Active / Inactive / All tab, opening on Active, ordered by size.
2. Product form: offer only hazmat classes whose special service is active.
3. Remove `create` from `PackageResource` (page, route and header action). Check the Edit
   form (Managers) for the same free-text fields and file what it finds.

## Done when

Tests for the Box Sizes default tab, the hazmat options, and that the Packages list has no
create action and `/packages/create` is not routed.

## Comments

### 2026-10-16 — done

  volume. The Active filter went, since the tabs replace it.

  already holding an inactive class keeps it listed so an edit does not clear it.

  **New** button on a Shipment's Packages table. `PackagePolicy::create()` now refuses
  everyone, so nothing else can bring it back by accident.
