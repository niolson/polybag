# End of Day lists carriers with no account, and working accounts say "Needs Setup"

> *This was generated by AI during the ui-review walk-through.*

Status: done

Source: [findings](../findings.md) E1, CA1, CR1; with E2–E4

Page or flow: End of Day (demo step 6); Carrier Accounts; Setup Wizard

Severity: medium

Call: before the demo

## Problem

- **E1 / CR1.** All six seeded carriers are active, so End of Day shows six identical End
  Shipping Day buttons, three for carriers with no account (DHL Express, Amazon Shipping,
  OnTrac).
- **CA1.** `CarrierAccount::connectionStatus()` calls a USPS or UPS account Connected only
  when it holds an OAuth token. But a USPS or UPS account can also authenticate with its own
  client credentials: `USPSConnector` and `UpsConnector` read `client_id` and
  `client_secret` from the `CarrierAccount` itself and have no global fallback.
  `hasUsableCredentials()` already accepts either (with the CRID for USPS, the account
  number for UPS), and FedEx's status uses it. So a valid client-credentials account (both
  did buy labels and quote rates in the review) shows "Needs Setup", and the Setup Wizard
  repeats it.

  The USPS credentials section of the form also says it "Overrides the global USPS
  credentials for shipments assigned to this account"
  (`CarrierAccountForm.php`); there are no global USPS credentials to override.
- **E2–E4.** Native `wire:confirm`; no description of the page; zero shown as "—".

## Fix

1. End of Day lists carriers with an active account or a label today; Generate Manifest is
   the primary action, End Shipping Day secondary.
2. Base USPS and UPS status on `hasUsableCredentials()`, as FedEx does: Connected when the
   account has its own usable OAuth token or client ID and secret (plus the CRID or account
   number); Needs Setup otherwise. The Setup Wizard reads the same method.
3. Reword the USPS credentials description to say what the fields are for this account,
   without the global-credentials claim.
4. Filament modal for End Shipping Day; one-line page description; 0 for zero.

## Done when

- Tests for the carrier list on End of Day.
- Status tests for USPS and UPS: client ID and secret with the CRID or account number and
  no OAuth token → Connected; an OAuth token → Connected; client ID without the secret, or
  without the CRID or account number → Needs Setup.

- End of Day lists a carrier when it has an active account (a `CarrierAccount`, or for
  Amazon Shipping an Amazon connection scoped to sell it), when a postage-selling Shopify
  connection dates its labels by it, or when it has a label on its current ship date.
  This reverses ADR-0006 decision 1's "lists every active carrier"; the ADR is amended.

  has a one-line description and shows 0 for no packages.

  section no longer claims to override global credentials, and its OAuth Status says
  when the account signs in with its own client ID and secret instead.

  done; End of Day no longer depends on it.
