# Generate Manifest always prints, and a multi-account run prints only its last form

> *This was generated by AI during the ui-review walk-through.*

Status: ready-for-agent

Source: [findings](../findings.md) E6; raised in review 2026-10-16

Page or flow: End of Day (demo step 6)

Severity: medium

Call: before the demo

## Problem

- **Generating and printing are one action.** `EndOfDay::generateManifest()` creates the
  form and then sends it to the document printer right away, unless `suppress_printing`
  is on for the whole install. A manager who only wants the form created, for example to
  print it later at another workstation or to keep a PDF, cannot do that.
- **A multi-account run prints only its last form.** `ManifestService` makes one USPS SCAN
  form per carrier account (and one per 10,000 packages) and saves each, image included,
  as its own `Manifest`. But it returns only `$lastImage`, so End of Day prints the last
  form and none of the earlier ones. Those forms reach the Manifests table and can be
  reprinted, but nothing says they were not printed, and the driver may leave without them.
  Ship dates do the same: `generateManifest()` loops over dates and prints each date's
  response, so there the rule is the same one, one print per response.
- **"Reprint" is ambiguous.** The Manifests table's button says only "Reprint", while the
  rest of the app uses Reprint for labels
  ([`release-polish/49`](../../release-polish/issues/49-wording-workflow-pages.md) left it
  as it is, saying it would become "Reprint Manifest" if changed).

What already works: every form USPS returns is saved with its image, and any row with an
image has a Reprint button. The `EXTERNAL-…` placeholder rows (packages USPS said were
already manifested) have no image, and so no button, which is correct.

## Fix

1. Two actions per carrier row: **Generate Manifest** (creates and saves, prints nothing)
   and **Generate & Print** (the current behavior). Make Generate & Print the primary
   button, since a driver needs the paper; Generate Manifest gray beside it.
   `suppress_printing` keeps overriding both.
2. Have `ManifestService::createManifest()` return every `Manifest` it created (or their
   images), and have Generate & Print send each one to the printer, not only the last.
   The success notification names how many forms were made and printed.
3. Rename the table's button to **Reprint Manifest**, and say "No image" in its place on a
   row without one, so an `EXTERNAL-…` row does not look broken.

## Done when

- A test that Generate Manifest saves a form and dispatches no `print-report`, and Generate
  & Print dispatches one.
- A test with two USPS accounts on one ship date: two `Manifest` rows, both with images,
  and two `print-report` dispatches.
- A test that the Manifests table shows Reprint Manifest for a row with an image and "No
  image" for one without.
