# Date-only columns show a day early, and a missing or past delivery date reads as late or on time

> *This was generated by AI during the ui-review walk-through.*

Status: ready-for-agent

Source: [findings](../findings.md) S11 (high), S1, M3

Page or flow: Package view, Shipments list and view, Ship page rate list

Severity: high — S11 misstates the ship date on the demo path (step 3)

Call: before the demo

## Problem

**S11.** `ship_date` and `deliver_by` are date columns, cast to UTC midnight, and three
entries format them with `->date(timezone: Location::timezone())`, which moves them to the
previous evening anywhere in the Americas. A label bought on Oct 16 shows Ship Date Oct 15.

- `app/Filament/Resources/PackageResource/Pages/ViewPackage.php` — Ship Date
- `app/Filament/Resources/ShipmentResource.php` — the Deliver By column and the Deliver By
  entry on the view

**S1.** `RateSelector::isOnTime()` returns false when a rate has no delivery date, so for a
military address every USPS rate is labeled "LATE" and the Ship page says "No options meet
the deliver-by date". PolyBag does not know either way.

**M3.** A FedEx sandbox rate quoted on Oct 16 said "Delivers Fri, Jul 28". The date has no
year, so it reads as next July, and as it is before the deadline it counts as on time.

## Fix

1. Drop `timezone:` from the three date-only entries. Grep for any other `->date(` with a
   timezone on a date column.
2. Give a classified rate three delivery states: on time, late, unknown. No date, or a date
   before today, is unknown.
3. Ship page: "No delivery estimate" for unknown; the "No options meet the deliver-by date"
   banner only when every rate has a date and all are late; show the year on a date outside
   the current year.
4. Automation keeps its current rule: a method with "Exclude rates that deliver after the
   due-by date" on still skips unknown dates, as its help text already says. Only the
   display changes here; changing what automation buys is a separate decision.

## Done when

- A test renders Ship Date and Deliver By with an America/New_York location and gets the
  stored date.
- A test classifies a dateless rate and a past-dated rate as unknown, and the Ship page
  shows neither as "LATE".
