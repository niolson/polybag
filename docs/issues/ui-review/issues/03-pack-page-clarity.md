# Scan & Pack: one meaning for Clear Shipment, a visible draft state, and the box named

> *This was generated by AI during the ui-review walk-through.*

Status: done

Source: [findings](../findings.md) P1, P2, P3; with P4, P7, P9, P10

Page or flow: Scan & Pack, demo step 2

Severity: medium

Call: before the demo

## Problem

- **P1.** The **Clear Shipment** button takes the items back out and keeps box and
  measurements (`clearPacking()`, behind a native `window.confirm()`); the **Clear Shipment**
  command barcode `%CCLEAR` leaves the Shipment (`clearShipment()`).
- **P2.** A Package Draft is saved in the background (`queueSave()`) once a box or item is
  scanned, with nothing on screen saying so.
- **P3.** Scanning a box code fills in the dimensions and never names the box.
- **P4, P7, P9, P10.** A partly packed line says "Not Packed"; Auto Ship has no explanation;
  the Packed count jumps sideways; Print Command Barcodes lights nothing in the sidebar.

## Fix

1. Rename the button "Unpack All Items" and confirm with a Filament modal; keep "Clear
   Shipment" for leaving.
2. Show "Draft saved" with the time beside the shipment header once a draft exists.
   (Discarding a draft from Pack is out of scope here.)
3. Show the box label and code beside the measurements.
4. "1 of 2" for a partly packed line; a tooltip on Auto Ship using the user form's own
   sentence ("Buy and print the cheapest on-time label as soon as a package is packed");
   reserve the − button's space; add Print Command Barcodes to Pack's active route pattern.

## Done when

Livewire tests for the button label and modal, the draft-saved indicator, and the box name
after a box scan.
