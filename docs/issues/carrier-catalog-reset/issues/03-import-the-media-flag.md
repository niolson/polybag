# Import the media flag through a connection's field mapping

Status: needs-triage

> *This was generated by AI during triage.*

## Parent

[PRD](../PRD.md), *Media Mail*. ADR-0006 decision 11.

## What to build

A seller whose product data lives in an external database can set the media flag from
it on import, just as they set barcode and weight today. They should not have to mark
each product by hand.

- The shipment-item field mapping gains a media field. `ImportReferenceResolver` writes
  it to `is_media` on the product it creates or updates, alongside `barcode` and
  `weight`.
- It has no default mapping. An unmapped field leaves the product's flag as it is. It
  never clears a flag someone set by hand.
- Accept the truthy and falsy spellings a SQL column is likely to hold. Anything else
  leaves the flag unchanged and logs a warning; it never fails the import.
- `docs/data-sources/database.md` lists it under *Fields with no default mapping*.

Filling the flag from Amazon's catalog is later work, recorded under *Media Mail* in the
PRD. It is not part of this issue.

## Acceptance criteria

- [ ] With the media field mapped, an import creates and updates products with the flag
      set from the source row
- [ ] With it unmapped, an import leaves an existing product's flag untouched
- [ ] An unrecognised value leaves the flag unchanged and does not fail the import
- [ ] The Database driver reference documents the field
