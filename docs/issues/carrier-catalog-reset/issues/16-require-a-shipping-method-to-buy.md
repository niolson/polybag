# A shipment needs a shipping method before a label is bought

Status: ready-for-agent

Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

[PRD](../PRD.md), *No shipping method*, which this replaces. Amends ADR-0006 decision 12
and the *Allowance* definition that follows from it.

## Why

A shipping method is what says which sources and services may sell for a shipment. With
no method, PolyBag asks every source it can reach, with no service list, and automation
buys any direct rate. Nobody decided that for the shipment. It was useful while
developing the app, and it is not something production should do.

A missing method is almost always a mapping gap. Import records the reference it could
not resolve in `shipping_method_reference`, *Unmapped Shipping References* lists them,
and an Amazon connection's default method already catches most Amazon service levels.
The fix is to map the reference or pick a method, not to quote everything.

Supporting the case also costs a second path through rating, source resolution, the
allowance and rules, each with its own special cases.

## What to build

A shipment with no shipping method cannot have a label bought. It can still be packed.

- **One check, worked out, not stored.** No new `ShipmentStatus`. A stored state would
  have to be kept in step with every method assignment and every alias that resolves an
  import. Put it on `Shipment` beside `isBlockedByPicking()`, from `shipping_method_id`.
- **Enforced on the server.** Rating returns no rates and issues no Offers for the
  package, and the purchase workflow refuses, so neither a stale page nor an old Offer
  can buy one. This includes the blind-purchase path.
- **Packing is allowed.** Packing is physical work, and the method can be fixed after.
  The Pack page shows that a method is missing, so the packer knows before walking the
  box to the Ship page.
- **The Ship page** shows the problem instead of rates, with a method picker for anyone
  allowed to edit the shipment. Choosing one re-rates.
- **Batch Ship** skips the package and gives the reason, as it does for picking
  (`BatchLabelService`).
- **Manual Ship** requires a method. Its field is currently optional, with "— None —".
- **Shipments list.** A *Needs shipping method* badge and filter. The Exceptions widget
  already counts unmapped references and should link to the same view.
- **Remove the no-method path.** With a method always present at rating and purchase:
  - `PostageSourceResolver` no longer asks every carrier for a null method, including
    `sellsAmazonShippingDirectly()`'s null branch.
  - `ShippingRateService::assignServices()` loses the unfiltered query, the PO Box and
    military guard that exists only because of it, and Amazon Shipping's
    `allDestinations` case. Check each before deleting: some may still serve a method
    whose services are all inactive.
  - `MethodSourceAllowance::kindsFor(null)`, `RuleEvaluator` and `OfferRequirements`
    lose their null-method cases. A *rule* with no method still applies to every method.
    Only a *shipment* with no method goes.
- **Seeders, `demo:reset`, `GenerateTestData` and factories** give every shipment a
  method. `ShipmentFactory` already does. Its `withoutShippingMethod()` state stays, for
  testing the block, and the tests that use it to exercise no-method rating are
  rewritten to assert the block instead. `FAKE_CARRIERS` local work needs a seeded method
  that lists the fake carriers' services.
- **Existing open shipments** with no method need no migration. They show as needing a
  method. There are no production tenants.
- **Docs.** Amend ADR-0006: decision 12 and the *Allowance* row of the terminology table.
  Replace the PRD's *No shipping method* section and question 4 with a pointer here.

## Acceptance criteria

- [ ] A package whose shipment has no method gets no rates and no Offers, and a purchase
      for it is refused on the server
- [ ] It can be packed, and the Pack page says a method is missing
- [ ] The Ship page offers a method picker, and choosing a method rates the package
- [ ] Batch Ship skips it with a reason
- [ ] Manual Ship cannot create a shipment with no method
- [ ] The Shipments list can filter to shipments needing a method
- [ ] No code path rates or buys for a null method
- [ ] `demo:reset` and the seeders leave no open shipment without a method
- [ ] ADR-0006 and the PRD record the change
