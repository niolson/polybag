# Shopify sells real catalog services

Status: needs-triage

Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

[PRD](../PRD.md), *Source mapping*, *Shipping method* and *Ship dates*. ADR-0006 decisions
1, 2, 5 and 9.

## What to build

The `Shopify` carrier and its 22 catalog rows go. A shipping method lists real
services, says whether Shopify may sell them, and says whether Shopify may choose for
itself. A Shopify blind offer is an offer of a real service through Shopify.

- **The Shopify mappings.** `14` created the source mapping table. This issue writes the
  Shopify rows: the 21 established `carrier:service` pairs from `CarrierSeeder`, outward,
  one code per service.
  - They are written once, by migration, not by `CarrierSeeder`. The reference-data sync
    runs on every start and would restore a row someone had removed. A Shopify mapping
    decides what Shopify is offered for, so removing one must stick.
- **The catalog.**
  - Author USPS First-Class Package International Service
    (`FIRST-CLASS_PACKAGE_INTERNATIONAL_SERVICE`) and USPS Priority Mail Express
    International (`PRIORITY_MAIL_EXPRESS_INTERNATIONAL`). The direct USPS adapter
    already accepts both codes.
  - Add a `DHL Express` carrier with no adapter, and its Express Worldwide service with
    `service_code` `P`, DHL's own product code. A later direct DHL integration then needs
    no remapping. Name the carrier *DHL Express*, not *DHL*: DHL eCommerce is a
    different network with different pickups, and needs its own row if a source ever
    reports it.
  - Shopify's *Preferred services* screen lists everything the shop can buy, and Express
    Worldwide is its only DHL entry (`shopify-shipping-carrier/02`). Probes of `D`, `K`,
    `L`, `N`, `U`, `W`, `X` and `Y` all missed. Seed nothing else for DHL.
  - USPS Media Mail exists from `02`, and carries its requirement over from `04`.
  - Every UPS code Shopify uses already exists.
  - Remove the `Shopify` carrier, its rows, `ShopifyAdapter::CARRIER_NAME` as a catalog
    name, `AUTO_SERVICE_CODE` as a catalog row, and `05`'s transitional name lookup for
    Shopify.
- **The method's source policy is its own table.** This issue creates it, because
  *Shopify may sell* is the first source setting. `12` and `13` add to it rather than to
  `shipping_methods` (ADR-0006 decision 5, option O).
  - `shipping_method_postage_sources`: `shipping_method_id` (deleted with the method),
    `source_kind`, `unlisted_services`, timestamps. Unique on
    `(shipping_method_id, source_kind)`.
  - `source_kind` is the `PostageSourceKind` enum `14` introduced and rules use (`07`):
    `direct`, `shopify`, `amazon`.
  - `unlisted_services` is `none` or `any`: whether the source may sell beyond the
    method's listed services.
    - For Shopify, `any` means offering `auto`.
    - For Amazon Buy Shipping, it means *any service* (`13`).
    - Direct takes only `none`.

    Each source kind declares the values it accepts, and the model refuses any other.
    Kinds with different values get different labels on the form, *Allow Shopify's choice
    (`auto`)* and *Any service*, so nobody sees the shared column name.
  - **A row means the source may sell for the method, and no row means it may not.**
    Every method gets a `direct` row when it is created, which is "direct on by default".
    Deleting that row turns direct off. *Shopify may sell* is a `shopify` row.
  - **Admin-only, by its own policy.** The rows are edited in a relation manager on the
    method page, beside the rules. `ShippingMethodPostageSourcePolicy` allows create,
    update and delete to an Admin and viewing to a Manager. A Manager still edits the
    method's services, due-by and OTDR settings and rules, which pick within what the
    rows allow. The policy lives on the model, so a field added later cannot slip past
    it the way a per-field lock on a Manager-editable form could.
  - Add a model factory with states for each kind and for `any`. Update the seeders that
    create shipping methods, so every seeded method has its `direct` row.
  - Rating and selection load a method's rows once, with the method.
  - From here, `07`'s rule form reads the sources a method allows from these rows.
  - **Left for later: a nullable `client_id`.** A client's row overriding the method's
    row for that kind is where per-client allowances would go (ADR-0006, *Foreseen, not
    decided*). Nothing in this issue needs it.
- **A method may list no services when a row allows unlisted services**, as a `shopify`
  row with `auto` does. `NoActiveCarrierServicesException` is thrown only when the method
  has nothing at all to buy.
- **Rating.**
  - The Shopify task offers one blind offer per method service that has a Shopify
    mapping, keeping the weight bands for UPS Ground Saver, plus `auto` when it is
    allowed.
  - A blind offer's identity is the source and its `CarrierService`, or `auto`.
- **Purchase.**
  - `preferredRateSelection` is the mapping's outward code.
  - The requested preference stays audit metadata, and the service is never recorded as
    `confirmed` (ADR-0003 decision 7). The Label records no `carrier_service_id` for it
    (`02`).
- **Unattended.**
  - The sole-choice rule is generalized: a blind purchase is made when Shopify is the
    only source that can sell for this method and package, and it yields exactly one
    offer.
  - A method with Shopify, `auto` and no services therefore lets Shopify choose.
  - A method with `auto` and a service needs a rule.
- **Ship dates.** A blind offer that requests a service is dated by that service's
  carrier. `auto` is dated by the connection's *Date Shopify's choice as* from `08`.
- **Rules.** *Shopify, a service* from `07` names a real service, and *Shopify, auto*
  names `auto`.

## Acceptance criteria

- [ ] On a method listing USPS Ground Advantage and UPS Ground, with Shopify allowed, a
      Shopify order whose client has opted in shows a blind offer for each beside the
      direct rates
- [ ] `auto` appears only when the method allows it. A method with Shopify, `auto` and
      no services is valid and quotes
- [ ] Batch ship buys `auto` unattended on that method. With `auto` and one service it
      buys nothing unless a rule names one
- [ ] A purchase sends the mapped code (for example `usps:GroundAdvantage`) and records
      no confirmed service
- [ ] A Shopify label requesting UPS Ground is dated by UPS's policy, and an `auto` label
      by the carrier its connection names
- [ ] No `Shopify` carrier or "Shopify's …" service exists, and the mapping table holds
      the 21 pairs
- [ ] A Shopify mapping removed by hand stays removed after `app:sync-reference-data`
- [ ] A new method has a `direct` row. Without one, the method gets no direct rates
- [ ] A Manager can see a method's postage-source rows but not create, change or delete
      them
- [ ] A `direct` row with `unlisted_services = any` is refused
- [ ] No carrier account can be created for DHL Express
