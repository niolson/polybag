# Mark products as media, and sell direct USPS Media Mail only to Packages that qualify

Status: needs-triage

Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

[PRD](../PRD.md), *Media Mail*. ADR-0006 decisions 10 and 11.

## What to build

An operator marks products as media. A Package whose items are all media is offered USPS
Media Mail from our own USPS account, on a shipping method that lists it. Every other
Package is never offered it, on the Ship page or in automation.

- **Product flag.** `products` gains `is_media`, a boolean, off by default, beside
  `contains_alcohol`. It is set on the product form, and the product table gets a bulk
  action and a filter for it. It is a declaration by the seller and is never inferred. The
  factory gains a state for it.
- **Qualification.** A Package qualifies when it has at least one item and every
  `PackageItem` has a product marked media. An item with no product never qualifies,
  and neither does a Package with no items, such as one from Manual Ship. Put this in
  one place that every source will call, and have it take the content class, so a later
  class needs no second copy.
- **The requirement lives on the service** (guideline 13). `carrier_services` gains
  `required_contents`, a nullable enum of the contents a service is valid for. Null
  means no requirement. `media` is its only case. `CarrierSeeder` authors USPS Media Mail
  (`MEDIA_MAIL`) with `required_contents = media`. It reaches PO Boxes and military
  addresses, like the other USPS services.
- **Why an enum on the service and a boolean on the product.** Every service requires at
  most one class, so one column holds it, and a new class is a new case rather than a
  reshaped column. On the product, each class is a separate declaration by the seller,
  and one enum there would assert that a product can only ever qualify for one class. The
  classes that could follow:
  - **Bound Printed Matter.** Would be a case plus `is_bound_printed_matter`. ADR-0006
    decision 11 does not author it.
  - **Documents**, for international express document products such as DHL `D`. Would be
    the same shape, and nothing here needs it.
  - **Library Mail** is not a class. It takes Media Mail's contents plus a condition
    that sender and recipient are qualifying institutions, which is a fact about the
    shipper, not the product.
  - **Contents that rule services out** do not belong in this enum. Hazmat, alcohol and
    lithium batteries already make a Package require a special service, and services
    that cannot provide it are excluded (`SpecialServiceResolver::resolveProductRequiredCodes()`).
    `required_contents` is only the opposite case: contents that make a service allowed.
- **Direct USPS.** Add `MEDIA_MAIL` to `UspsAdapter::SHIPPER_PACKAGING_INDICATORS`. Take
  its rate indicator or indicators from a logged sandbox `search` response, as
  `packaging-form-and-carrier-identity/05` did, not from memory. Library Mail stays
  excluded, and the comment above the constant is updated.
- **A rate carries its catalog identity.** The drop needs to know which `CarrierService`
  a rate is for, and a lookup by carrier name and code string is exactly what the reset
  removes. So this issue lays the plumbing every later slice reads:
  - `RateResponse` gains `carrierServiceId` and `carrierId`. Direct adapters set both
    from the service and carrier they quoted. The Amazon adapter sets them in `04`.
  - `shipping_offers` stores both, and `rateFromOffer()` restores them. A Ship-page
    purchase then knows its catalog service and carrier from the server's copy, not the
    browser's. The carrier id dates the purchase in `08`, rename-safe.
  - `package_labels` records `carrier_service_id` at purchase, beside the
    `normalized_carrier_id` it already has. That is what lets a report name USPS Ground
    Advantage once, whatever sold it. A blind purchase never sets it from its request:
    what Shopify was asked for stays the requested preference (ADR-0003 decision 7).
- **The drop.** A rate whose `carrierServiceId` names a service with a
  `required_contents` is dropped for a Package that does not qualify for that class. The drop happens before the
  quote log and before its Offer is issued, beside `PackagingFilter::keepCompatible()` in
  `ShippingRateService::getShippingRates()`.
- **Rule pre-selection is not a way round the drop.** ADR-0005 found that shipping-rule
  pre-selection bypasses a post-quote filter unless the filter also runs where a
  pre-selected rate is resolved. The drop must run there too, so a *Use* rule naming
  Media Mail buys nothing for a Package that does not qualify.

## Acceptance criteria

- [ ] A product can be marked media on its form and in bulk, and is not media by default
- [ ] A Package whose items are all media, on a method listing USPS Media Mail, is quoted a
      direct USPS Media Mail rate on the Ship page
- [ ] A Package with one non-media item, an item with no product, or no items at all gets
      no Media Mail rate, and no `ShippingOffer` or `rate_quotes` row is written for one
- [ ] A *Use* rule naming USPS Media Mail does not buy it for a Package that does not
      qualify
- [ ] For a qualifying Package, automation may choose Media Mail when it is the cheapest
      acceptable rate
- [ ] Library Mail is still never offered
- [ ] A direct rate carries its `CarrierService` and carrier ids, the Offer stores them,
      and a Ship-page purchase restores them from the Offer rather than from the browser
- [ ] A direct Label records the `CarrierService` it was bought as, and a Shopify Label
      records none

## Comments

- **2026-09-24** — Second review: `RateResponse::$carrierServiceId` moved here from `07`,
  because this drop needs it first. The carrier id and the Offer and Label columns
  came with it, so `08` can date a purchase without waiting for the rules work.
- **2026-09-24** — Storage settled: `products.is_media`, a boolean, and
  `carrier_services.required_contents`, a nullable enum whose one case is `media`. The
  classes considered and why only one exists are listed under *What to build*.
- **2026-09-24** — **Implemented** on `feature/media-mail-for-qualifying-packages`
  (awaiting review; no Media Mail label bought in the sandbox yet).
  - One qualification rule, `Package::qualifiesFor(ContentClass)`. `PackageData` carries its
    result as `qualifyingContents`, so it is part of the rate request's fingerprint. Unmarking a
    product after a Media Mail quote therefore retires the offer. Deploying retires every
    outstanding offer once, because the fingerprint's shape changed.
  - The drop is `Shipping\ContentsFilter`, run beside `PackagingFilter` in
    `getShippingRates()` and on a rule's resolved pre-selected rate. Direct adapters stamp
    `carrierId` / `carrierServiceId` through the `IdentifiesCatalogServices` concern. It finds
    the carrier by name until `05`. Where two rows share a code, the oldest wins.
    `RuleEvaluator` stamps the rule's own rate.
  - A *Use* rule naming Media Mail, on a Package that does not qualify, falls through to rate
    shopping. This is the same as a pre-selected rate the packaging rules out (ADR-0005). The
    Package gets the cheapest acceptable rate the method allows, never Media Mail.
  - A Media Mail rate dropped for its contents does not mark its source packaging-ineligible
    for the sole-blind-purchase test. If it did, Shopify could become the sole choice and buy
    the same Media Mail blind.
  - `CarrierSeeder` restores `required_contents = media` on every sync, not only when it
    creates the row.
  - The Label's `carrier_service_id` restricts deletion. The Offer's two ids are null on
    delete.
  - A Package with no shipping method that qualifies may be sold Media Mail by automation,
    because with no method the allowance is every direct service (decision 12).
  - **Open:** every logged sandbox response returns Media Mail twice, `SP` under both
    `MACHINABLE` and `NONSTANDARD`, at one price. Both are shown, and automation takes the
    first on a tie. Which one a given parcel should be bought as, and whether USPS re-rates
    the wrong one, is unverified.
