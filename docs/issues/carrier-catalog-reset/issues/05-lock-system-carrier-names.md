# Lock system carrier names, and give carriers an editable display name

Status: done

Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

[PRD](../PRD.md), *Catalog* and *Constraints from the app*. ADR-0006 decision 1, as
amended 2026-09-25.

## What to build

A carrier's `name` is its key. The app, the seeders, the adapter registry, alias
matching, ship dates and the logo files all find a carrier by it, and the carrier form lets
an operator change it. So renaming UPS breaks rating and purchase, and on the next start
the reference-data sync creates a second `UPS`. This makes the key immutable where the app
depends on it, and moves what an operator wants to change into a separate label.

- **System carriers.** A new `carriers.is_system` boolean. The seeders set it on every
  carrier they create or find: USPS, UPS and FedEx, and the `Shopify` and `Amazon` rows
  until `09` and `12` remove them. `11` and `09` set it on Amazon Shipping, OnTrac and DHL
  Express when they seed them. A migration sets it on existing rows by name.
  - The `Carrier` model refuses to change a system carrier's `name`, and refuses to delete
    one. Throw from `updating` and `deleting`, so tinker and seeders are held to it as
    well as the form. Deactivating stays allowed, and it is how an unwanted carrier is
    hidden: the next sync would recreate a deleted one anyway.
  - The carrier form shows a system carrier's name read-only and hides its delete action.
    `is_system` is never editable, and never fillable from a request.
- **Custom carriers.** A carrier an operator creates has `is_system = false`. It can be
  renamed, and deleted under the existing guard (not while `normalizedPackages()` exist).
  It has no direct integration, so it can have no carrier account.
  - If a seeder later seeds a carrier whose name matches a custom one, it adopts the row
    and marks it system. It keeps the row's id, services and `display_name`.
- **`carriers.name` becomes unique.** It is a key now. Check local and server databases
  for duplicates before the migration runs. The seeder bug above may already have made
  one.
- **`display_name`.** A nullable string an operator may set on any carrier, system or
  custom, for a rebrand or house style ("US Postal Service"). `Carrier::label()` returns
  `display_name ?? name`.
  - The seeders never write it, so an operator's value survives `app:sync-reference-data`.
    For a rebrand of our own, a data migration changes `name`.
  - **The UI shows `label()`** wherever it shows a carrier row: the carrier list and edit
    page, `CarrierLogoColumn`'s text, the carrier-service and special-service groupings
    (`CacheService`, `SpecialServiceResource`), shipping-rule labels, the unmapped
    observed-services page, End of Day, the Setup Wizard, the location form's account
    list, and the Carrier Account form's default account name.
  - **Everything else keeps `name`:** the registry, `packages.carrier`, `RateResponse`,
    labels, exports, channel fulfillment, alias matching (`CarrierAlias`,
    `CarrierNormalizer`, the typed-name match in `UnmappedObservedServices`),
    `ShipDateService`, and logo lookup (`Carrier::logoUrlForName()` keys the SVG file by
    name).
  - Where the UI has only a carrier's name as text, as the package list, label batches and
    packing reports do with `packages.carrier`, it shows the label of the carrier row that
    name matches exactly (`Carrier::labelForName()`). Text that matches no row is shown as
    it is. `packages.carrier` itself stays free text.
- **Name constants.** `Carrier::USPS`, `Carrier::UPS` and `Carrier::FEDEX` replace the
  string literals in `app/` and `database/seeders/`. Once names are fixed these lookups
  are correct, and a constant keeps a typo from becoming a silent miss. The sites today:
  - `CarrierAccount::connectionStatus()` and `hasUsableCredentials()`;
  - `EditCarrierAccount`'s USPS and UPS OAuth actions, and `HasFedexRegistration`;
  - `LocationResource::hasActiveFedexCarrier()`, `ListCarrierServices`, and the Setup
    Wizard;
  - `ManifestService`, `UspsAddressValidator`, `FedexSandboxInternationalRates`,
    `RateResponse`, `AmazonBuyShippingAdapter`'s FedEx packaging check, and the three
    FedEx test-case commands;
  - each adapter's `getCarrierName()`, the registry's registrations including
    `FAKE_CARRIERS` in `AppServiceProvider`, and the three reference-data seeders.

  Migrations keep literals, so they never depend on a model. `ShopifyAdapter::CARRIER_NAME`
  and `AmazonBuyShippingAdapter::SOURCE_NAME` stay as they are until `09` and `12` remove
  the rows. Tests may keep literals.
- **Carrier accounts.** The Carrier Account form offers only carriers with a registered
  direct adapter that takes a `CarrierAccount`, and `CarrierAccount` refuses to save
  against any other carrier. That replaces the form's name check against `Amazon`, and
  closes the gap that let an account be created for `Shopify`. Amazon Shipping's adapter
  (`15`) takes a connection instead, so each direct adapter declares which kind of account
  it uses.

Not here: the registry stays keyed by carrier name, and moving rating off carrier names
is `06`'s (ADR-0006 decision 4). End of Day's move to `normalized_carrier_id` is `08`'s.

## Acceptance criteria

- [x] Renaming or deleting a system carrier is refused by the model, and the form offers
      neither. Deactivating one works
- [x] A custom carrier can be created, renamed, and deleted while no package records it
- [x] Two carriers cannot share a `name`
- [x] Running `app:sync-reference-data` twice creates no carrier, marks every seeded
      carrier system, and leaves an operator's `display_name` in place
- [x] With `display_name` set on UPS, the carrier list, carrier services, shipping rules,
      End of Day and the Carrier Account form show it. Rating, buying, the label,
      `packages.carrier` and the logo are unchanged. Clearing it shows `UPS` again
- [x] The Carrier Account form lists only USPS, UPS and FedEx, and saving an account for
      any other carrier is refused, `Shopify` included
- [x] No `'USPS'`, `'UPS'` or `'FedEx'` literal naming a carrier row or carrier of record
      remains in `app/` or `database/seeders/` outside the constants. External vocabulary
      and display text keep theirs
- [x] The existing suite passes

  have failed the rename test. The seeder bug was found at the same time: every start

- **2026-09-25** — Third review found more name lookups again, including
  `CarrierAccount::hasUsableCredentials()`, which returns false for a renamed carrier and
  so stops it rating, and `CarrierServiceSpecialServiceSeeder`. Rather than keep chasing
  them, the maintainer chose to lock system carriers' names, and to give operators a
  `display_name` for rebrands and house style. The `carriers.adapter` key is dropped
  (ADR-0006, 2026-09-25 amendment). The name lookups become correct, and this issue
  shrinks from moving about thirty call sites to a guard, a column, and constants. It is
  now `ready-for-agent`. Retitled from *Key direct integrations by `carriers.adapter`*.
- **2026-09-25** — Done on `feature/lock-system-carrier-names`. Migration
  `2026_09_25_163149` adds `display_name` and `is_system`, makes `name` unique, and refuses
  to run while duplicate names exist. `Carrier::seedSystem()` is what every seeded carrier
  goes through. The Carrier Account restriction reads a `UsesCarrierAccount` marker on
  the *shipped* adapter classes (`CarrierRegistry::takesCarrierAccount()`), so test fakes
  and `FAKE_CARRIERS` never change which carriers may have an account. The carrier factory

  Covered by `tests/Feature/SystemCarrierTest.php`, which checks `display_name` on the
  carrier list, the Carrier Account form and End of Day. The carrier-service and
  shipping-rule labels read the same `label()` but have no test of their own.
- **2026-09-25** — Code review: two fixes. The Setup Wizard's next steps put the display
  name, and the connection name before it, into raw HTML. Both are escaped now. And the
  string-backed carrier columns (packages, label batches, packing reports) ignored
