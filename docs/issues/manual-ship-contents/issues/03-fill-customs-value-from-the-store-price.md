# Fill a Product's customs value from the store's price

Status: done
Category: enhancement
Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

`manual-ship-contents`. Split from `01` on 2026-11-02: `01` adds `products.customs_value`,
edited by hand; this fills it from the product catalog sync.

## Problem

For goods that are sold, the customs value is the sale price. When there is no order (a
scan-to-add Manual Ship, a replacement), the store's price is the best stand-in. The
catalog sync already brings in each Product's weight, HS code and origin, but not its
price, so every Product's customs value must be typed in.

## Proposal

The catalog sync fills `customs_value` where the Product has none. It never overwrites
one, whether a person typed it or an earlier sync filled it.

- **Fill-only.** Add `customs_value` to `ProductCatalogSync::FILL_ONLY_FIELDS`. Amazon
  prices are often set by a repricing app and can change hundreds of times a day, and two
  connections for one Client can price the same SKU differently. If the sync overwrote,
  the value would track whichever store synced last and count every change as an update.
  A price change in the store reaches PolyBag only when someone edits the Product. A
  per-connection "update customs values from store prices" setting was considered and
  left for later, if someone asks for it.
- **Shopify:** the variant's `price`, the price the store sells at. Never
  `compareAtPrice`, which is the crossed-out "was" price. The shop's currency and tax
  setting come from `shop { currencyCode taxesIncluded }`, read once per sync.
- **Amazon:** `attributes.purchasable_offer`, which the listings read already returns, so
  no `offers` and no change to the request. Take the entry for the connection's
  `marketplace_id` with `audience` `ALL` (not a business-buyer price), and its
  `our_price[0].schedule[0].value_with_tax` in that entry's `currency`. Ignore
  `discounted_price` and any scheduled sale for now.
- **Only in the Client's currency.** A price in any other currency fills nothing.
- **No tax-inclusive prices.** Skip a Shopify shop whose `taxesIncluded` is not `false`,
  and an Amazon marketplace whose prices include tax: every one but Amazon.com and
  Amazon.ca (`AmazonMarketplace::pricesIncludeTax()`). Mexico shows prices with IVA in
  them, so it is skipped with Brazil, though triage first grouped it with the US and CA. A catalog price has no
  pre-tax version, and the rate depends on where the buyer is, so the VAT cannot be
  taken back out. `tax-inclusive-prices/01` fixes the order side and does not change this.
- **A price of 0 is no value**, as a weight of 0 is. A free sample or gift variant fills
  nothing.
- Order imports leave `customs_value` alone: an order line's price is what one buyer paid,
  after discounts, in their currency.

## Findings (2026-11-04)

- **Amazon**, from the 2026-10-28 listings captures of the production seller account (US
  marketplace, about 29,700 SKUs; summary in
  `.scratch/manual-ship-contents/amazon-purchasable-offer.md`):
  `purchasable_offer` is on about 98% of listings. Every one has audience `ALL`, currency
  `USD`, one `our_price` entry with one schedule entry, and `value_with_tax` as its only
  key. None has a `discounted_price` or a price of 0. Most also carry
  `minimum_`/`maximum_seller_allowed_price`, a repricer's bounds. The account has no
  business-buyer prices, so their shape is unverified; the `audience` check covers them.
  `value_with_tax` is Amazon's field name everywhere: on the US marketplace it excludes
  sales tax, which Amazon adds at checkout.
- **Shopify**, both development stores (`.scratch/manual-ship-contents/shopify-catalog-price-*.json`):
  `shop.currencyCode` `USD`, `taxesIncluded` `false`. A 250-variant page of
  `id sku price compareAtPrice` plus `shop` requested 25 points, so adding `price` to the
  catalog query costs nothing that matters.

## Acceptance criteria

- [x] A Shopify catalog sync fills an empty customs value from the variant's `price` when
      the shop's currency is the Client's, and never from `compareAtPrice`
- [x] An Amazon catalog sync fills an empty customs value from the marketplace's `ALL`
      audience `our_price` when its currency is the Client's
- [x] A Product that already has a customs value keeps it
- [x] A price of 0, a price in another currency, a Shopify shop with `taxesIncluded`, and
      an Amazon marketplace whose prices include tax fill nothing
- [x] An order import does not write `customs_value`

## Comments

- 2026-11-04: Implemented. Sources put `customs_value` and its currency
  (`ProductCatalogSync::CUSTOMS_VALUE_CURRENCY`) on each catalog item;
  `ProductCatalogSync` drops a value not in the Client's currency, and `customs_value` is
  fill-only. `ProductCatalogSync::customsValueFrom()` treats 0, and anything past the
  column's decimal(8,2), as no value. `ShipmentItemImporter` strips `customs_value` from
  order lines, so a custom field mapping cannot set it either. Tests in
  `ProductCatalogSyncTest`, `AmazonProductCatalogSyncTest` and `ShipmentItemImporterTest`.
