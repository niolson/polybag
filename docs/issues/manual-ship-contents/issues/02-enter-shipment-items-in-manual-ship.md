# Enter Shipment items in Manual Ship

Status: needs-triage
Category: enhancement
Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

`manual-ship-contents`. Separate from `01` (Product value), which it can use but does not
need.

## Problem

Manual Ship takes an address and a parcel but no contents. Without scan-to-add, the Draft
Shipment it buys from has no items and no value, so an international Manual Ship has
nothing to put on a customs form. With scan-to-add, the contents are only what can be
scanned, so an item with no Product (a sample, a replacement part) cannot be entered.

A Shipment's items can already be added, edited and deleted afterwards in the Shipment
resource's items relation manager (`ShipmentItemsRelationManager`), but not in the Manual
Ship flow. Editing items there on an imported Shipment also has no guard: the next
`update` import from the source rewrites them.

## Proposal

- Optionally, behind a setting, let Manual Ship take items: a repeater of description,
  SKU, quantity, unit value, weight, HS code and country of origin. Each line may be
  picked from the Product catalog to prefill it, or typed freehand. Show the Shipment's
  currency beside the values.
- Sum the lines into the Shipment's `value` unless one is entered.

## Questions for triage

- Should the same editing be offered on Pack for an imported Shipment, and what happens
  when the source next updates those items? Today a re-import replaces them, and changed
  items make a printed pack slip out of date.
- Who may enter items? `warehouse-permissions/01` proposes that Manual Ship be Manager- or
  Admin-only.
- Does packing validation count entered items as the expected contents?

## Acceptance criteria

- [ ] With the setting on, Manual Ship can record items, freehand or from a Product
- [ ] The Draft Shipment and the bought Label's customs lines carry those items and values
- [ ] With the setting off, Manual Ship behaves as it does today
