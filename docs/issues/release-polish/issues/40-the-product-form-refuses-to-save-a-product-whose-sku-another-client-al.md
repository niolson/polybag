# The product form refuses to save a product whose SKU another client also has, so the EU refusal's fix cannot be made

> *This was generated by AI during release-polish pass 4.*

Status: ready-for-agent

Pass: 4 — bug (review of EU product identifiers)

Page or flow: product form, after an EU consumer label is refused

Severity: medium — multi-client extension; the refusal sends the user to a form that will not save

Verified: confirmed. Line numbers are at `12592f33`; this area is unchanged on `dfd842c5`.

## Problem

Imports file Products by client and SKU (`ImportReferenceResolver.php:110-113`,
`firstOrNew(['client_id' => …, 'sku' => …])`), so two Clients selling the same SKU get
two Products, as `AGENTS.md` intends. The product form validates `sku` with
`->unique(ignoreRecord: true)` (`app/Filament/Resources/ProductResource.php:68-71`),
which checks every client's rows. Editing either Product fails with "The sku has already
been taken." The `product_identifier_missing` refusal
(`app/Services/Customs/CustomsReadiness.php:298-305`) tells the user to add the
Manufacturer Part Number on the product form and links there, and the form is the only
place a part number can be typed for an Amazon or Shopify client without one. So that
client's EU consumer labels stay refused until the other client's product is renamed.
Creating the same SKU for a second client by hand fails the same way.

## Evidence

`tests/Feature/Probes/ProductIdentifiers/SameSkuTwoClientsFormTest.php`:

```php
<?php

use App\Filament\Resources\ProductResource\Pages\EditProduct;
use App\Models\Client;
use App\Models\Product;
use App\Models\User;
use App\Services\ShipmentImport\ImportReferenceResolver;
use Livewire\Livewire;

it('lets a part number be added to a product whose SKU another client also imported', function (): void {
    $this->actingAs(User::factory()->admin()->create());
    $first = Client::factory()->create();
    $second = Client::factory()->create();
    $resolver = app(ImportReferenceResolver::class);

    // Two clients' imports file the same SKU, one Product each, as designed.
    $resolver->productIdFor(['sku' => 'MUG-001', 'name' => 'Mug'], $first);
    $resolver->productIdFor(['sku' => 'MUG-001', 'name' => 'Mug'], $second);
    $product = Product::where('client_id', $second->id)->where('sku', 'MUG-001')->sole();

    // The EU refusal sends the user to the product form to add the part number.
    Livewire::test(EditProduct::class, ['record' => $product->id])
        ->fillForm(['manufacturer_part_number' => 'MFG-67890'])
        ->call('save')
        ->assertHasNoFormErrors();

    expect($product->fresh()->manufacturer_part_number)->toBe('MFG-67890');
});
```

## What to build

Scope the rule to the record's client:
`->unique(ignoreRecord: true, modifyRuleUsing: fn (Unique $rule, Get $get) => $rule->where('client_id', $get('client_id') ?? <default client>))`,
taking the default client when the client select is hidden (single-client mode).
