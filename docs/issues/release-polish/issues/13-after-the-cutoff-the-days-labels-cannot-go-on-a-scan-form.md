# After the USPS cutoff, or once the day is ended, the day's labels can no longer go on a SCAN form

> *This was generated by AI during release-polish pass 4.*

Status: done — 2026-10-14

Pass: 4 — bug (review of End of Day)

Page or flow: End of Day, Generate Manifest

Severity: medium — End of Day is demo step 6; the Generate Manifest button disappears for labels the operator just bought, with no message, and those labels never reach any form.

Verified: confirmed. Line numbers are at `12592f33`; this area is unchanged on `7649fe0c`.

## Problem

`EndOfDay::manifestablePackages()` (`app/Filament/Pages/EndOfDay.php:217`) takes
only Labels whose `ship_date` equals `ShipDateService::getShipDate()` *now*. That date moves
forward in two ordinary ways:

- at the carrier's cutoff hour (`ShipDateService.php:54`; USPS is seeded with 20, 8 PM in the
  location's time zone), whether or not anyone ended the day;
- when someone presses End Shipping Day (`ShipDateService.php:48`).

Either way, every unmanifested label dated today drops out of `unmanifested_count`, the
Generate Manifest button is hidden, and nothing later picks them up, because the current
ship date only moves forward. The package count has a second test for this
(`lastEndOfDayForCurrentBatch()`); the manifest query has none. Ending the day before
generating the form is a natural order to click the two buttons in, and the page's confirm
text gives no warning. A demo whose location clock is past 8 PM (a Pacific afternoon against
the `America/New_York` default) hits the first case.

Not `end-of-day-count/01`: that issue is about Shopify `auto` labels in the package count,
and explicitly leaves the manifest count alone.

## Evidence

```php
beforeEach(function (): void {
    Location::factory()->default()->create(['timezone' => 'UTC']);
    $this->usps = Carrier::factory()->usps()->create(['active' => true]); // 8 PM cutoff
    $this->travelTo(now('UTC')->next('Wednesday')->setTime(10, 0));
    $this->actingAs(User::factory()->admin()->create());
});

it('still offers a SCAN form for labels dated today once the USPS cutoff has passed', function (): void {
    Package::factory()->usps()->create(['carrier_account_id' => null, 'ship_date' => now()->toDateString()]);

    $this->travelTo(now()->setTime(20, 30)); // after the 8 PM cutoff, day never ended

    Livewire::test(EndOfDay::class)
        ->assertSet('carrierSummary.0.unmanifested_count', 1);
});

it('still offers a SCAN form for the day just ended', function (): void {
    Package::factory()->usps()->create(['carrier_account_id' => null, 'ship_date' => now()->toDateString()]);

    Livewire::test(EndOfDay::class)
        ->call('endShippingDay', $this->usps->id)
        ->assertSet('carrierSummary.0.unmanifested_count', 1);
});
```

Both fail with `Failed asserting that 0 matches expected 1.` A control case (same Label,
10 AM, day not ended) passes with 1. Probe:
`tests/Feature/Probes/EodFakesSettings/ManifestAfterCutoffTest.php`.

## What to build

Manifest every unmanifested direct Label whose `ship_date` is on or before
the carrier's current ship date (bounded, say, to the last week so nothing ancient is swept
in), grouped per ship date so each form gets its own `mailingDate`. Or, smaller: also
accept the previous pickup day's date. Product decision: whether End Shipping Day should
warn when unmanifested labels remain for the date it is closing.
