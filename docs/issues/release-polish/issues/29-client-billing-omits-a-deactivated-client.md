# Client Billing omits any client that has been deactivated, including the periods it was active

> *This was generated by AI during release-polish pass 4.*

Status: ready-for-agent

Pass: 4 — bug (review of reports and billing)

Page or flow: Client Billing

Severity: medium — It loses the final invoice of a client who leaves. This is off the live demo, but it is billing.

Verified: confirmed. Line numbers are at `12592f33`; this area is unchanged on `dfd842c5`.

## Problem

The summary keeps only `clients.active = true`
(`ClientBillingReport.php:283`). `updatedClientId()` resets an inactive client to null
(`:62-69`), which silently drops the Billable Event Log back to the summary table. Yet the
client picker lists inactive clients (`:89-93`). A 3PL that deactivates a departing client
on October 31 cannot produce that client's October bill.

## Evidence

```php
it('bills last month for a client deactivated since', function (): void {
    $client = Client::factory()->create(['active' => true]);
    $shipment = Shipment::factory()->create(['client_id' => $client->id]);
    Package::factory()->shipped()->create(['shipment_id' => $shipment->id, 'cost' => 8.00, 'shipped_at' => '2026-10-10 15:00:00']);

    $client->update(['active' => false]);

    $row = octoberBilling();

    expect($row)->not->toBeNull()
        ->and((float) $row->total_postage)->toBe(8.00);
});
```

Show every client with billable activity in the period, active or
not. Allow an inactive client in the Billable Event Log.
