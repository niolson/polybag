# A second overlapping Batch Ship run fails with an unhandled exception and batches nothing

> *This was generated by AI during release-polish pass 4.*

Page or flow: batch ship

Severity: low — it needs two people batching the same orders at the same moment, and
nothing is bought twice.

Verified: plausible. Line numbers are at `12592f33`.

## Problem

Validation and draft creation are separate steps. When two submissions validate the same
Shipment before either commits, the second `createBatchReadyDraft()` finds the first one's
non-empty draft and throws `PackageDraftInvalidException`
(`app/Services/PackageDrafts/EloquentPackageDraftWorkflow.php:122-124`, or `:128-130` once
the first has shipped it).

`createBatch()` lets the exception escape the transaction, and the bulk action does not
catch it (`app/Filament/Resources/ShipmentResource.php:571-578`). So the whole second batch
rolls back, including the Shipments that did not overlap, and the user sees a server error
instead of a "skipped" notice.

## Scenario

Two Managers select overlapping Shipments and submit Batch Ship within the same second. The
first batch runs. The second request errors and creates nothing.

## What to build

Treat the re-check under the Shipment lock as an ineligibility, as validation does: skip
that Shipment with its reason and continue.
