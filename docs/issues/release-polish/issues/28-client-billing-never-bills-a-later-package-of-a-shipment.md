# Client Billing dates a whole Shipment by its first Package, so a Package that ships in a later period is never billed

> *This was generated by AI during release-polish pass 4.*

Status: done

Pass: 4 — bug (review of reports and billing)

Page or flow: Client Billing (summary, Billable Event Log, both CSV exports)

Severity: high — It misstates billing: postage and label fees for the later Package never appear on any invoice.

Verified: confirmed. Line numbers are at `12592f33`; this area is unchanged on `dfd842c5`.

## Problem

`buildPackageSubquery()` groups shipped Packages by Shipment and dates the
group `MIN(p.shipped_at)` (`app/Filament/Pages/Reports/ClientBillingReport.php:322-337`).
Every date filter and export then tests that one date (`:176-178`, `:251-253`, `:404-405`,
`:438-439`). Take a Shipment whose first Package shipped on September 30 and whose second
shipped on October 2 (a backorder, or a split order):

- A September invoice run on October 1 includes only the first Package, because the
  second has not shipped yet.
- The October report leaves the whole Shipment out, because its date is still
  September 30.

So the second Package's postage and label fee are never billed. If September is re-run
later, it changes: it picks up October's Package.

## Evidence

```php
it('bills a package in the period it shipped, even when its shipment began in an earlier one', function (): void {
    $client = Client::factory()->create(['active' => true, 'label_fee_per_package' => 1.00]);
    $shipment = Shipment::factory()->create(['client_id' => $client->id]);

    // Package 1 shipped and was invoiced in September; package 2 shipped in October.
    Package::factory()->shipped()->create(['shipment_id' => $shipment->id, 'cost' => 8.00, 'shipped_at' => '2026-09-30 15:00:00']);
    Package::factory()->shipped()->create(['shipment_id' => $shipment->id, 'cost' => 9.00, 'shipped_at' => '2026-10-02 15:00:00']);

    $row = octoberBilling();

    expect((int) $row->package_count)->toBe(1)
        ->and((float) $row->total_postage)->toBe(9.00);
});
```

`octoberBilling()` sets the table's `date_range` filter to 2026-10-01 – 2026-10-31 and
returns the first summary record. The setup is in the probe file. A control test, where
the same Shipment ships wholly in October, passes.

## What to build

Filter Packages by `shipped_at` inside the package subquery, so each
Package bills in its own period. Then decide where the per-Shipment fees fall, which is a
product decision. The natural choice is the period of the Shipment's first shipped
Package: charge `pick_fee_base` and the extra-item fee only on that line, and later lines
carry postage, label fee and materials alone.
