# Print Both stamps the pick batch's summary as printed even when the summary could not be printed

Page or flow: View Pick Batch (`/pick-batches/{id}`), Print Both and Picking Summary in print mode

Severity: medium — a print is recorded that did not happen (the column is not displayed anywhere yet)

Verified: observed in the browser on 2026-11-17, configuration B

## Problem

With **Print Without Preview** on and no print agent reachable, click **Print Both**. The page shows "No document printer configured. Go to Workstation Settings. No pack slips were sent or recorded as printed." Then query `pick_batches`: batch 1 has `summary_printed_at = 2026-11-17 18:57:13`. The summary was never printed. `ViewPickBatch.php:69` and `:109` set `summary_printed_at` as soon as the print event is dispatched, before the browser reports anything, unlike the pack slips, which are recorded only on the browser's receipt. The message also says nothing was recorded as printed, which is wrong for the summary.

Screenshot: `.scratch/release-polish/picking-pack-slips/B-4-print-both-no-agent.png`

## What to build

Record `summary_printed_at` only when the browser confirms the summary job was sent, the way the pack-slip receipts work, or stop recording it if nothing reads it.
