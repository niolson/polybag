# USPS validation ignores the Shipment's location when choosing the account

## Problem

`UspsAddressValidator::resolveAccount()` (`app/Services/Validation/UspsAddressValidator.php:155-161`) calls `resolveForShipment($carrierId, null, $client_id)`. FedEx resolves with `location_id` (`CarrierAccount::resolveForAddressValidation()`). Where USPS accounts are scoped only to locations, no account is found. USPS then reports unavailable on every run, so no attempt is ever recorded. The Shipment is retried every five minutes and fails the command each time. Where a global account also exists, a located Shipment is validated, and billed, on the global account rather than its location's.

**Scenario.** Multi-location on, one USPS account scoped to (Location A, no client), and no global USPS scope. A Shipment at Location A, with Google off, is never validated and keeps `shipments:validate` exiting with failure.

## What to build

Use `CarrierAccount::resolveForAddressValidation()` for USPS too.
