## Findings

- **The billing CSV exports a different period than the table when a date is cleared.**
  `exportCsv()` falls back to the current month (`ClientBillingReport.php:108-110`), while
  the table applies no bound for a null date (`:176-178`). Plausible.
- **The "last month" default is the current month on the 31st** (and on March 29–31).
  `now()->subMonth()` overflows, for example October 31 becomes October 1
  (`ClientBillingReport.php:169,172,244,247`). Use `subMonthNoOverflow()`. Plausible.
- **Volume Report drill-downs open Shipments by `created_at`**, the import date
  (`VolumeReport.php:204-226`). The report counts Packages by `ship_date`, and the channel
  and method links drop the date range entirely, so the linked list never matches the
  number clicked.
- **"Shipments by User" counts Packages.** It uses `COUNT(*)` over packages
  (`UserShipmentsReport.php:95,151`) and groups by `users.name` (`:98`), so two users who
  share a name merge into one row. The dashboard chart "Shipped Shipments" also counts
  Packages (`ShippedShipmentsChart.php:13`).
- **Week grouping uses ISO week numbers with the calendar year** (`YEAR()` with
  `WEEK(…, 3)`), so late December can read `2025-W01` (`VolumeReport.php:271`,
  `UserShipmentsReport.php:202`). SQLite uses `%W`, a different numbering.
- **Architecture: billing rates are read live, not stored when a Label is billed.** Client
  fees, `box_sizes.materials_cost` and `products.handling_surcharge` are read at report
  time, so re-running a past period after a price change gives a different bill. File and
  wait.
- **Architecture: the rollup has no `client_id`, and the Volume Report has no Location or
  Client filter**, so a 3PL cannot see volume per client except through Client Billing.
  File and wait.
- **Product decision: duties are never billed.** Prepaid duties (`package_labels.duties_cost`,
  DDP) appear nowhere in Client Billing, though the 3PL pays them.
