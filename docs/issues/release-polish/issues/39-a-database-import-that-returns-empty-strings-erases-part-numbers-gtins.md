# A Database import that returns empty strings erases part numbers, GTINs, HS codes and origins typed by hand

> *This was generated by AI during release-polish pass 4.*

Status: ready-for-agent

Pass: 4 — bug (review of EU product identifiers)

Page or flow: Database connection import

Severity: high — loses data a person entered, and the lost part number then refuses every EU consumer label for that product

Verified: confirmed. Line numbers are at `12592f33`; this area is unchanged on `dfd842c5`.

## Problem

`ImportReferenceResolver::productIdFor()`
(`app/Services/ShipmentImport/ImportReferenceResolver.php:97-108`) drops only `null`
values before writing over the Product (`fn ($value): bool => $value !== null`).
`FieldMapper::map()` (`app/Services/ShipmentImport/FieldMapper.php:30-42`) passes column
values through unchanged, and nothing between `DatabaseSource::fetchShipmentItems()` and
`ShipmentItemImporter` turns a blank into null (the shipment row has such a step,
`ShipmentRowPreparer.php:142`; item rows do not). Many ERP schemas, and every SQL Server
`NOT NULL DEFAULT ''` column, return `''` for "no value". So a connection that maps
`manufacturer_part_number`, `gtin`, `hs_tariff_number` or `country_of_origin` (the four
fields `eu-product-identifiers/01` added to the mapping) blanks the Product's value on
every import of a row that has none. The PRD's stated rule is that "an empty metafield
leaves a hand-entered value alone"; Shopify honors it by mapping blanks to null, the
Database driver does not. The same holds for `barcode`, `description` and `weight`.
Unchanged on `origin/main`.

## Evidence

`tests/Feature/Probes/ProductIdentifiers/BlankImportedIdentifierTest.php`:

```php
<?php

use App\Models\Product;
use App\Services\ShipmentImport\FieldMapper;
use App\Services\ShipmentImport\ImportReferenceResolver;
use Illuminate\Foundation\Testing\RefreshDatabase;

uses(RefreshDatabase::class);

it('leaves hand-entered customs fields alone when a Database row returns empty strings', function (): void {
    $product = Product::factory()->create([
        'sku' => 'SKU-1',
        'manufacturer_part_number' => 'HAND-MPN',
        'gtin' => '00012345600012',
        'hs_tariff_number' => '610910',
        'country_of_origin' => 'PT',
    ]);

    // A SQL row whose optional columns are '' rather than NULL, as the
    // Database driver hands it over.
    $item = (new FieldMapper(['shipment_item' => [
        'sku' => 'sku', 'mpn' => 'manufacturer_part_number', 'gtin' => 'gtin',
        'hs' => 'hs_tariff_number', 'origin' => 'country_of_origin',
    ]]))->mapShipmentItem(['sku' => 'SKU-1', 'mpn' => '', 'gtin' => '', 'hs' => '', 'origin' => '']);

    app(ImportReferenceResolver::class)->productIdFor($item, $product->client);

    $product->refresh();
    expect($product->manufacturer_part_number)->toBe('HAND-MPN')
        ->and($product->gtin)->toBe('00012345600012')
        ->and($product->hs_tariff_number)->toBe('610910')
        ->and($product->country_of_origin)->toBe('PT');
});
```

Failed asserting that two strings are identical.
-'HAND-MPN'
+''

## What to build

In `productIdFor()`, treat a blank string as absent: filter with
`filled()` (trimming strings) instead of `!== null`, keeping `false` for `is_media`.
That puts the rule in the one place every source passes through, so the next source
cannot reintroduce it.
