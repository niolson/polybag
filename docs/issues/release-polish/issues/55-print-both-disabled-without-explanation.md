# Print Both on a pick batch is greyed out with no reason until "Print Without Preview" is switched on

> *This was generated by AI during release-polish pass 1.*

Status: done — 2026-11-18

Pass: 1 — picking and pack-slip walk-through

Page or flow: View Pick Batch (`/pick-batches/{id}`)

Severity: medium — a disabled control with no explanation looks broken

Verified: observed in the browser on 2026-11-17, configuration B

## Problem

On a new pick batch the header shows a toggle, **Print Without Preview**, then **Picking Summary**, **Pack Slips**, a faded **Print Both**, and the batch actions. **Print Both** is disabled (`->disabled(fn () => ! $this->printMode)`), with no tooltip or text saying why. Switching **Print Without Preview** on enables it and also turns **Picking Summary** and **Pack Slips** from "open in a new tab" into "send to the printer" without changing their labels. Nothing tells the user that the same two buttons now do something different.

With the toggle on and no print agent, Print Both shows "No document printer configured. Go to Workstation Settings. No pack slips were sent or recorded as printed." which is clear.

Screenshots: `.scratch/release-polish/picking-pack-slips/B-4-print-both-disabled.png`, `.scratch/release-polish/picking-pack-slips/B-4-print-both-no-agent.png`

## What to build

Either hide Print Both while the toggle is off, or give it a tooltip ("Turn on Print Without Preview to print"). Consider labels that say what each button does in each mode.
