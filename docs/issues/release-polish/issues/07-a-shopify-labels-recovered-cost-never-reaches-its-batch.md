# A Shopify label's recovered cost never reaches its batch row or the batch total

> *This was generated by AI during release-polish pass 4.*

Status: ready-for-agent

Pass: 4 — bug (review of label purchase and automation)

Page or flow: batch ship and the batch view

Severity: low — the batch view understates spend. Reports and billing read the Package,
which does get the cost.

Verified: plausible. Line numbers are at `12592f33`.

## Problem

A blind purchase reports no cost, so `GenerateLabelJob` stores `cost = null` on the batch
item and adds 0 to `total_cost` (`app/Jobs/GenerateLabelJob.php:61-70`). The hourly
`ShopifyLabelCostRecorder` later writes the exact cost to `package_labels.cost` and
`packages.cost` (`app/Services/ShopifyLabelCostRecorder.php:309-340`). It never writes
`label_batch_items.cost` or `label_batches.total_cost`.

## Scenario

A batch buys 10 Shopify labels. An hour later every Package has its cost, but the batch
still shows blank costs and a total of $0.00.

## What to build

Either of these:

- Read each batch item's cost through its Label, found by tracking number as
  `LabelBatchItem::serviceDisplayName()` does, and sum the batch total from those.
- Have the recorder update both batch rows when it writes the cost.
