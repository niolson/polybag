# In scan-to-add mode, an inactive box alias that is also a product barcode blocks the product

> *This was generated by AI during release-polish pass 4.*

Status: ready-for-agent

Pass: 4 — bug (review of the Pack page and box sizes)

Page or flow: Pack page, scan-to-add mode

Severity: low — needs an inactive alias equal to a SKU or barcode; off the usual path

Verified: plausible. Line numbers are at `12592f33`; this area is unchanged on `7649fe0c`.

## Problem

`pack.blade.php:103` shows "Box size inactive" for an inactive alias before
dimensions are set, without asking whether the scan is a product. In validate mode
(`pack.blade.php:116`) the product wins (`isInactiveBoxCode && !isProduct`), as
`box-size-seed-data/02`'s comment says ("A typed code that is also a product in the order
still goes to the product"). In scan-to-add mode the product lookup is server-side, so an
inactive box, which can never be applied, still blocks adding that product until
dimensions are typed.

## Evidence

Scenario: scan-to-add on, a Shipment with no items, an inactive box with
alias `12345`, a product of the Shipment's client with barcode `12345`. Scan `12345` before
any dimensions: a warning, and the product is not added.

## What to build

In scan-to-add mode, send an inactive-alias scan to `addItemByScan()`
and warn only when that reports not found.
