# A Label voided after the day it shipped stays in the volume and spend rollup, so void-and-rebuy counts twice and refunded postage is still counted

> *This was generated by AI during release-polish pass 4.*

Status: ready-for-agent

Pass: 4 — bug (review of reports and billing)

Page or flow: Dashboard (`StatsOverview`, `ShippedShipmentsChart`, `CostPerPackageTrend`, `CarrierBreakdownChart`), Volume Report

Severity: high — It misstates package counts and postage spend on the dashboard and the Volume Report, both on the demo path (step 5, then step 7).

Verified: confirmed. Line numbers are at `12592f33`; this area is unchanged on `dfd842c5`.

## Problem

Every dashboard figure and the Volume Report read `daily_shipping_stats`.
`stats:aggregate` rebuilds only the dates it is given: by default yesterday and today
(`app/Console/Commands/AggregateShippingStats.php:76-77`), and every 15 minutes `--today`
(`bootstrap/app.php:19-27`). A void nulls `ship_date` and sets the Package to unshipped
(`app/Models/Package.php:1124-1150`). The only thing it triggers is
`InvalidateDashboardCache`, which forgets widget caches
(`app/Providers/EventServiceProvider.php:20-22`) and does not rebuild the voided Label's
date. So a Label voided two or more days after its ship date stays in that day's rollup
row for good, with its cost. If the Package is bought again, the new Label is counted on
its own date as well. The rollup row is only corrected if someone runs
`stats:aggregate --from` over that date by hand. The same applies to a Shopify void the
synchronizer picks up late, and to a Package deleted or archived after shipping.

## Evidence

```php
it('drops a voided label from the rollup once the scheduled rebuild runs', function (): void {
    $threeDaysAgo = Carbon::today(Location::timezone())->subDays(3)->toDateString();

    $package = Package::factory()->shipped()->create(['carrier' => 'USPS', 'service' => 'Ground', 'cost' => 12.50]);
    DB::table('packages')->where('id', $package->id)->update(['ship_date' => $threeDaysAgo]);

    // The nightly rollup counted it on the day it shipped.
    $this->artisan('stats:aggregate', ['--from' => $threeDaysAgo, '--to' => $threeDaysAgo])->assertSuccessful();
    expect((int) DailyShippingStat::sum('package_count'))->toBe(1);

    // Voided today (refunded by the carrier), then the scheduled rebuilds run.
    $package->fresh()->clearShipping(VoidReason::Operator);
    $this->artisan('stats:aggregate')->assertSuccessful();
    $this->artisan('stats:aggregate', ['--today' => true])->assertSuccessful();

    expect((int) DailyShippingStat::sum('package_count'))->toBe(0)
        ->and((float) DailyShippingStat::sum('total_cost'))->toBe(0.0);
});
```

## What to build

When a Label is voided, re-aggregate its own date. `VoidedLabel`
already carries `shipDate` on `PackageCancelled`. A queued listener can run the rebuild
for that one date, as `SyncShopifyLabelCostsCommand` does for the dates it costs. Do the
same for Package deletes. A periodic wider rebuild (say the last 35 days, nightly) would
also catch any path that is missed.
