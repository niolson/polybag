# A Label voided while its Shopify export is in flight leaves the dead number on the order

> *This was generated by AI during release-polish pass 4.*

Status: ready-for-agent

Pass: 4 — bug (review of the label lifecycle)

Page or flow: a void right after purchase, for a direct Label on a Shopify order

Severity: low — it needs a void within a second or two of the `fulfillmentCreate` call, and
the re-export then fails visibly.

Verified: plausible.

## Problem

`ExportShippedPackage` runs seconds after purchase. Suppose the void lands while
`ShopifySource::exportPackage()` is waiting on Shopify:

1. `clearShipping()` deletes the claimed `PackageExport` row.
2. `takeBackFromChannel()` (`EloquentPackageLabelWorkflow.php:133`) reads a null
   `shopify_fulfillment_id`, so it cancels nothing.
3. The export then returns the fulfillment ID.
   `PackageExportService::rememberShopifyFulfillment()` (`PackageExportService.php:565`) finds
   no active Label with that number, and only logs a warning.

Shopify keeps a fulfillment with the voided number and a closed fulfillment order. When the
Package is re-shipped, its export is refused. Because `_has_voided_label` is set, it fails
permanently.

## Scenario

1. Buy a direct Label for a Shopify order.
2. Void it from the Packages table while the queued export's `fulfillmentCreate` is still
   outstanding.

The Shopify order is fulfilled with the voided number, no "Sales channel not updated" warning
appears, and the next export fails permanently.

## What to build

Either of these:

- When the export finds its Label voided, store the fulfillment ID on the voided Label row
  (match by tracking number, voided or not), and run
  `ShopifyFulfillmentCanceller::cancelAfterVoid()` from there.
- Have the export take the Package row lock and re-check the status before calling Shopify.
