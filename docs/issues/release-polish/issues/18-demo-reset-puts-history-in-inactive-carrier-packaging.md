# `demo:reset` records most fabricated history in inactive carrier packaging of the wrong carrier

> *This was generated by AI during release-polish pass 4.*

Status: done — 2026-10-14

Pass: 4 — bug (review of the Pack page and box sizes)

Page or flow: `demo:reset`, Packages list and Package view of history

Severity: low — demo data, visible on the Packages list and Package view, not on a core step's main screen

Verified: plausible. Line numbers are at `12592f33`; this area is unchanged on `7649fe0c`.

## Problem

`app/Console/Commands/DemoReset.php:383` picks each fabricated Package's box
from `BoxSize::pluck('id')`, every row. Since #400, every install has 35 inactive carrier
rows from the reference-data sync next to the 13 common ones, so about 73% of fabricated
shipped Packages get an inactive carrier box, regardless of the carrier `pickCarrier()`
chose: a UPS Ground Package in a "FedEx 25kg Box" or a USPS one in a "UPS Tube". Each
change was right alone; together they make the demo history inconsistent with ADR-0005
(carrier packaging is valid only with its carrier). Billing is unaffected: both sets have
a zero or null `materials_cost`.

## Evidence

Scenario: fresh install (reference sync seeds the carrier catalog), common
set loaded, `demo:reset`. Query fabricated packages joined to `box_sizes`: most have
`active = 0` and a `carrier_packaging` whose carrier differs from `packages.carrier`.

## What to build

Pick from `BoxSize::active()` with `carrier_packaging` null (own
packaging), or pick a carrier box only for its own carrier.
