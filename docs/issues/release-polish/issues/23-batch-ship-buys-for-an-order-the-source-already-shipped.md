# Batch ship buys a Label for an order the import marked shipped by its source after the batch was selected

> *This was generated by AI during release-polish pass 4.*

Status: ready-for-agent

Pass: 4 — bug (review of order reconciliation and PII retention)

Page or flow: batch ship (`GenerateLabelJob`), auto-ship

Severity: medium — a second parcel and second postage for an order already shipped elsewhere, the case the PRD exists to prevent; needs an import to land inside a batch run

Verified: confirmed. Line numbers are at `dfd842c5`.

## Problem

PRD decision 4 says buying for a shipped order is a manager's reship. The
attended paths enforce that against the database: Pack checks `ShipmentPolicy::reship()`
on mount, on `saveDraft()` and on `ship()` (`app/Filament/Pages/Pack.php:173`, `:341`,
`:378`), and the Ship page authorizes `PackagePolicy::ship()`, which calls `reship`. The
unattended purchase does not. `BatchLabelService` skips a shipped Shipment only when the
batch is selected, and `GenerateLabelJob` then calls `PackageShippingWorkflow::autoShip()`,
whose `notReadyToShip()` re-reads only `cancelled`
(`app/Services/PackageShipping/EloquentPackageShippingWorkflow.php:233-237`). Since `06`,
`07` and `08`, an import can move an open Shipment with a ready Package to
`Shipped`/`source` at any import interval, so a batch selected before that import and run
after it buys anyway. `updateShippedStatus()` then leaves the Shipment `Shipped`/`source`,
so nothing on the Shipment shows that PolyBag also shipped it.

## Evidence

The probe never reaches a refusal: the workflow goes on toward rating and
fails for an unrelated reason. The same setup with the status set to `cancelled` returns
`Order Cancelled` (`tests/Feature/ShipmentStatusOriginTest.php`, "is refused when
cancelled after the package was loaded").

```php
<?php

use App\Contracts\PackageShippingWorkflow;
use App\DataTransferObjects\PackageShipping\PackageAutoShippingRequest;
use App\Enums\PackageStatus;
use App\Enums\ShipmentStatus;
use App\Enums\ShipmentStatusOrigin;
use App\Models\Package;
use App\Models\Shipment;

it('refuses an unattended purchase for an order the source shipped after the batch was selected', function (): void {
    $shipment = Shipment::factory()->create();
    $package = Package::factory()->for($shipment)->create(['status' => PackageStatus::Unshipped]);
    $package->load('shipment');

    // The import closes it between batch selection and the job.
    Shipment::whereKey($shipment->id)->update([
        'status' => ShipmentStatus::Shipped,
        'status_origin' => ShipmentStatusOrigin::Source,
    ]);

    $result = app(PackageShippingWorkflow::class)->autoShip($package, new PackageAutoShippingRequest(cleanupOnFailure: false));

    expect($result->success)->toBeFalse()
        ->and($result->message)->toContain('shipped');
});
```

## What to build

In `notReadyToShip()`, beside the `cancelled` read, refuse an
unattended purchase when the Shipment is now `Shipped` and was not when the batch began
(or simply when it is `Shipped` with no user who may reship), with a result like
`shipmentCancelled()` that leaves the Package intact. The batch item then fails with a
reason a person can read.
