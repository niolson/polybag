## Findings

### The same "package already has a label" condition gets two titles and two remedies

- Severity: high. On the Ship and reprint path, the packer gets different advice for the same
  situation, depending on how they got there.
- Locations:
  - `Ship.php:526` — "Already Shipped — This package already has a label. Print it again, or
    void it from the Packages page."
  - the shipping workflow — "Package State Changed — This package already has a label
    ({tracking}). Reprint it, or void it first, from the Packages page."
  - `Ship.php:171` — "Already Shipped — This package has already been shipped."
- Recommendation: one message everywhere: "Already Shipped — This package already has a label
  ({tracking}). Reprint it, or void it from the Packages page." The workflow must stop using
  "Package State Changed" for this case; that title means someone else changed the package at
  the same moment.

### The purchase success toast has a different title on every page

- Severity: high. Buying a label is the main demo action.
- Locations:
  - `Ship.php:626` — "Package Shipped — Tracking: {n}"
  - `Pack.php:475` — "Auto Shipped — Tracking: {n} via {carrier} ({service}) - ${cost}"
  - `ManualShip.php:301` — "Shipped — {summary}"
  - batch — "Batch #{id} completed"
- Recommendation: "Label Bought" as the title on Ship, Pack and Manual Ship. The event is a
  Label purchase (`CONTEXT.md`), and "Shipped" reads as the Shipment's status. Pack may keep
  "Auto Ship" as a prefix to mark the toast automatic. The body is "Tracking {n} via
  {carrier} {service} — ${cost}" when the source reports service and price. A Shopify blind
  purchase reports neither, so its body is "Tracking {n} via {carrier}"; do not invent fields
  for it.
- Leave the batch notification out of this rename. A batch completion is not one purchase:
  it can hold many labels, partial failures or no successes at all. Keep its counts and its
  outcome titles ("completed", "completed with errors", "failed",
  `app/Notifications/BatchLabelCompleted.php:30`); only its wording is in `50`.

## The capitalization convention

The slices disagreed about notification titles. Counted across all four lists, unique
notification titles split roughly 97 Title Case to 88 sentence case, once the
non-notification rows are removed. The split runs by area:

- **Title Case** covers almost the whole demo path: Pack, Ship, Manual Ship, End of Day, the
  purchase and Offer results, and customs readiness.
- **Sentence case** sits in the Filament resource CRUD and admin toasts, which are mostly off
  the demo path.

**Recommendation: Title Case for every title, label, heading and button, including notification
titles. Sentence case for bodies, helper text and descriptions.**

- The demo path already follows it.
- Some notification titles are also enum labels, which are Title Case.
- Converting the sentence-case titles is about the same amount of work as converting the other
  way, but these edits land on pages off the demo path.

Titles that are comma phrases follow the same rule: "Voided, Not Recorded" and "Recorded, Not
Voided".

This replaces the sentence-case recommendation for notification titles in issues `47` and
`48`.
