# A Shipment a manager cancels stays in its pick batch, so its items are still picked and its slip still prints

> *This was generated by AI during release-polish pass 4.*

Status: ready-for-agent

Pass: 4 — bug (review of pack slips and pick-batch printing)

Page or flow: Edit Shipment → View Pick Batch (Picking Summary, Pack Slips, Print Both)

Severity: medium — the picking summary misstates what to pull; picking is a demo extension, not the core path

Verified: confirmed. Line numbers are at `12592f33`; this area is unchanged on `dfd842c5`.

## Problem

`PickBatchService::removeFromActiveBatches()` exists so that "pickers don't
pull items for a completed order". It is called when PolyBag marks a Shipment shipped
(`app/Models/Shipment.php:334`) and when an import closes one
(`app/Services/ShipmentImport/SourceClosureApplier.php:90`). It is not called when a
manager changes the status on Edit Shipment
(`app/Filament/Resources/ShipmentResource/Pages/EditShipment.php:55-91`), which records
the change and an audit row and stops there. The cancelled (or manually shipped) Shipment
keeps its `pick_batch_shipments` row, so:

- `PickBatchService::summaryRows()` (`app/Services/PickBatchService.php:243`) still adds
  its quantities to the summary, and `total_shipments` still counts it.
- `PickBatchService::packSlipRun()` (`:195`) still includes it, and `PackSlipRenderer`
  draws slips without checking status, so a slip and tote are printed for a cancelled
  order. Redemption skips it, which is the only place status is checked.
- Its `picking_status` stays `batched`.

The two automated paths are correct; the manual path, which `order-reconciliation` added
the Manager origin for, is the one that misses it.

## Evidence

`tests/Feature/Probes/PackSlips/CancelledShipmentInPickBatchTest.php`:

```php
<?php

use App\Enums\PickingStatus;
use App\Enums\ShipmentStatus;
use App\Filament\Resources\ShipmentResource\Pages\EditShipment;
use App\Models\Product;
use App\Models\Shipment;
use App\Models\ShipmentItem;
use App\Models\User;
use App\Services\PickBatchService;
use App\Services\SettingsService;
use Livewire\Livewire;

it('drops a Shipment a manager cancels from its in-progress pick batch', function (): void {
    $manager = User::factory()->manager()->create();
    $this->actingAs($manager);
    app(SettingsService::class)->set('picking_enabled', true, 'boolean');

    $product = Product::factory()->create(['name' => 'Widget']);
    $kept = Shipment::factory()->create(['picking_status' => PickingStatus::Pending]);
    $cancelled = Shipment::factory()->create(['picking_status' => PickingStatus::Pending]);
    ShipmentItem::factory()->create(['shipment_id' => $kept->id, 'product_id' => $product->id, 'quantity' => 1]);
    ShipmentItem::factory()->create(['shipment_id' => $cancelled->id, 'product_id' => $product->id, 'quantity' => 5]);

    $batch = app(PickBatchService::class)->createFromShipments(collect([$kept, $cancelled]), $manager);

    Livewire::test(EditShipment::class, ['record' => $cancelled->id])
        ->fillForm(['status' => ShipmentStatus::Cancelled->value])
        ->call('save')
        ->assertHasNoFormErrors();

    expect($cancelled->fresh()->status)->toBe(ShipmentStatus::Cancelled);

    $rows = app(PickBatchService::class)->summaryRows($batch->fresh());

    expect($rows[0]['quantity'])->toBe(1)                                   // fails: 6, the cancelled order's 5 included
        ->and(app(PickBatchService::class)->packSlipRun($batch->fresh())->shipmentIds)->toBe([$kept->id]);
});
```

## What to build

In `EditShipment::afterSave()`, when the status moved off `open`, call
`PickBatchService::removeFromActiveBatches()`, as the two automated paths do. Better, move
the call into one place that every status change passes through (a `Shipment` saved hook
on a status change away from `open`), so a fourth path cannot miss it. Optionally,
`packSlipRun()` and `summaryRows()` could also skip non-open Shipments as a second guard.
