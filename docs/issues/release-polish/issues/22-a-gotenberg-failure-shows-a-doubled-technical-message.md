## Problem

`GotenbergService::pdfFromView()` throws "PDF renderer unavailable. Is
Gotenberg running?" or "PDF renderer returned an error: <Saloon message>"
(`app/Services/GotenbergService.php:28-31`). The pages put that under a title that already
says "PDF renderer unavailable" (`app/Filament/Pages/PrintPackSlips.php:265-269`,
`app/Filament/Resources/ShipmentResource/Pages/ViewShipment.php:84-88`), so a packer
reads the same phrase twice, then an internal service name, and on a 4xx/5xx a raw HTTP
client message. Nothing says what to do (retry, or tell an admin). The connector sets no
timeout (`app/Http/Integrations/Gotenberg/GotenbergConnector.php`), so a slow renderer
holds the request for Saloon's default 30 seconds per job, serially; a 500-Shipment Print
Both renders three jobs before anything is sent.

## Evidence

Stop the `gotenberg` container and press Print Pack Slip on a Shipment: a
danger toast "PDF renderer unavailable" / "PDF renderer unavailable. Is Gotenberg
running?". Nothing is recorded, which is correct.

## What to build

One user-facing message ("Pack slips could not be rendered. Try again;
if it keeps failing, ask an admin to check the PDF service.") with the exception logged,
and an explicit request timeout on the connector. Wording belongs with the pass 3 list.
