# `composer install` puts the executable bit back on every published Filament asset

> *This was generated by AI during release-polish pass 4.*

Page or flow: developer setup

Severity: low — off the demo path; a dirty tree, not a runtime fault.

Verified: confirmed (observed: a fresh `composer install` in a worktree of `12592f33` leaves all 38 files from #352 as `mode change 100644 => 100755`). Line numbers are at `12592f33`; this area is unchanged on `7649fe0c`.

## Problem

#352 cleared the bit in git only. `composer.json` runs `php artisan
filament:upgrade` in `post-autoload-dump`, which republishes the assets through
`Filesystem::replace()` with no mode, and Laravel then chmods to `0777 - umask()`
(`vendor/laravel/framework/src/Illuminate/Filesystem/Filesystem.php:228`). So every
`composer install` or `dump-autoload` makes them executable again, and the next
`git commit -a` re-commits it.

## What to build

Add a `post-autoload-dump` step after `filament:upgrade` that resets
`public/{css,js,fonts}/filament` files to 0644, or stop tracking the published assets and
publish them at build time.
