# Seed a demo that rates and ships on every carrier without hand edits

Status: ready-for-agent
Category: enhancement
Created: 2026-10-23

## Parent

`archive/live-store-demo/04`, which added `demo:provision`. Found running it end to end
on a hosted demo tenant on 2026-10-23, with a real Shopify store connected.

## Problem

`demo:provision` is meant to leave a demo needing no typing beyond the prospect
connecting their store. On that run four things had to be fixed by hand before all four
carriers would rate and buy:

1. **The seeded Location is not a real address and has no phone number.**
   `LocationSeeder` writes `123 Main St, Anytown, WA 98072`, with no `phone`, and
   `timezone` `America/New_York`.
   - UPS rejects the origin: every rate request returned `400 Invalid Origin` (`111538`).
     98072 is Woodinville, WA, and changing only the city to Woodinville fixed it.
   - FedEx rates without a phone number but will not buy:
     `shipper.contact.phoneNumber cannot be null`. `FedexAdapter` builds the shipper
     from the Location, and also uses its phone as the recipient's fallback.
   - The timezone does not match a Washington address, so the `DEMO_EXPIRES_AT` banner,
     which uses the Location's timezone, showed Eastern time.
2. **No channels.** `demo:provision` does not run `ChannelSeeder`, so a demo has none.
   The Shopify connection form requires `settings.channel_name`, chosen from active
   channels, so the prospect's store cannot be connected until someone creates one.
   (The demo Amazon Shipping connection is written with `channel_name` `'Amazon'`, a
   name, where the form stores a channel ID. It imports nothing, so this is harmless
   today, but its edit page will not show a valid channel.)
3. **Standard Ground lists too few services.** `ShippingMethodSeeder` gives Standard
   Ground only `USPS_GROUND_ADVANTAGE` and `GROUND_HOME_DELIVERY`, and `demo:provision`
   adds Amazon Shipping Ground. UPS Ground (`03`) and FedEx Ground (`FEDEX_GROUND`)
   are missing, so a demo cannot show a ground rate from all four carriers side by side.
4. **The demo Amazon Shipping connection's postage setting is `DoesNotSell`.** It
   should be `PackerAndAutomation`, so the demo can show automation (auto-ship, batch
   ship, shipping rules) buying Amazon Shipping, not only a packer on the Ship page.

## What is needed

1. **`LocationSeeder`:** a real, deliverable US address whose city, state and ZIP
   agree, a phone number, and the timezone of that address. It is shared with
   `DatabaseSeeder`, which is fine: development data should be valid for every carrier
   too. Use a number from the fictional 555-0100 to 555-0199 range, written in the
   form the Location form accepts, and check FedEx's sandbox takes it.
   This is a public repository: choose an address that is not a private person's home,
   such as a public building, or keep the street fictional only if all four sandboxes
   still accept it. City, state and ZIP must be real and match.
2. **Channels:** `demo:provision` seeds the channels a demo needs, at least one per
   store type a prospect can connect (Shopify, Amazon) and `Manual`, without
   `ChannelSeeder`'s `Test Channel`. Either add a demo seeder or give `ChannelSeeder` a
   way to skip the test row. Point the demo Amazon Shipping connection's
   `channel_name` at the Amazon channel's ID. If the Shopify connection form can
   preselect a channel when exactly one fits, do that too; otherwise the presenter
   picks from the seeded ones.
3. **Standard Ground:** add `03` (UPS Ground) and `FEDEX_GROUND` to Standard Ground in
   `ShippingMethodSeeder`, with `syncWithoutDetaching` as now. `FEDEX_GROUND` and
   `GROUND_HOME_DELIVERY` are FedEx's commercial and residential ground, so listing
   both lets rating pick by destination.
4. **Amazon postage:** `provisionAmazonShipping()` writes
   `postage_setting` `PostageSetting::PackerAndAutomation`. The form's help text says
   this field governs Buy Shipping for the connection's *own* Amazon orders, and that
   Amazon Shipping for orders from other channels "is set separately". Check which
   setting actually lets automation buy Amazon Shipping for a Shopify order through
   this connection, set that one to the equivalent of packer-and-automation as well,
   and say in a comment here which it was.

`demo:provision` stays idempotent: a second run must not duplicate channels or
services, and must leave anything the presenter changed (the Location in particular)
alone, as `firstOrCreate` does now.

- `DemoProvisionTest`:
  - The seeded Location has a phone, a city/state/ZIP that agree, and a matching timezone.
  - The Shopify and Amazon channels exist, without `Test Channel`.
  - Standard Ground lists all of `USPS_GROUND_ADVANTAGE`, `GROUND_HOME_DELIVERY`,
    `FEDEX_GROUND`, `03` and Amazon Shipping Ground.
  - The demo Amazon connection is `PackerAndAutomation` and points at the Amazon

  - A second run changes none of it.
- The tests that use `LocationSeeder` (`AddressDataTest`, `ManifestAfterVoidTest`,

- By hand on a fresh demo tenant: rate a package on Standard Ground and see all four
  carriers; buy a FedEx and a UPS sandbox label without editing the Location.

## Comments

- **Which setting lets automation buy Amazon Shipping for a Shopify order:** none beyond
  what was already set. Off-Amazon Amazon Shipping is not channel postage
  (`PostageSourceCandidate::isChannel()` is false for it) and its rates carry no observed
  service, so `RateResponse::sourceKind()` is `Direct`. Automation buys it under the
  method's `direct` row, once `offers_off_amazon_shipping` and the off-Amazon scope pick
  the connection. `postage_setting` is set to `PackerAndAutomation` anyway, so Buy
  Shipping on the connection's own orders is automatable if imports are turned on.
- Location: Woodinville City Hall, `17301 133rd Ave NE, Woodinville, WA 98072`, phone
  `(425) 555-0100`, `America/Los_Angeles`.
- **2026-10-27** — The postage setting is now a boolean, `sells_postage` (ADR-0006 decision 6,
  2026-10-26 amendment). `provisionAmazonShipping()` sets it to `true`, which is what
  `PackerAndAutomation` became.
