# Live-store demo: a prospect's own orders, with nothing done to their store

Status: reference

Repo: `polybag`

> *This was generated by AI during triage.*

Opened 2026-10-16. Builds on [`release-polish`](../release-polish/PRD.md), whose demo
script runs on `demo:reset` data.

## Why

The demo today runs on fabricated orders from the demo data tools. A stronger demo
connects the prospect's own Shopify store or Amazon seller account and shows their
actual open orders: picking a batch, printing the pack slips, printing the labels.

Demo mode already makes postage harmless for the direct carriers. `AppMode::Demo` forces
sandbox on (`connection-onboarding/01`), so USPS, UPS and FedEx labels are specimens. A
store is different. Today a demo tenant connected to a live store would do real things
to it.

The goal: **demo picking, pack slips and labels on a prospect's live orders, with nothing
written back to their store and no real postage bought.**

## What would go wrong today

1. **Fulfillments are written back to the live store.** `PackageExportService` exports a
   shipped Package to its originating connection. For Shopify that is `fulfillmentCreate`
   (`ShopifySource::exportPackage()`). Nothing on that path checks the mode. The real order
   is marked fulfilled with a sandbox tracking number. With the connection's
   `notify_customer` on, the real customer is emailed a tracking number that leads
   nowhere, and the merchant's own warehouse may skip an order Shopify now reports done.
   In multi-client mode it also exports to every active connection with global export on.
2. **Shopify Shipping buys real postage.** Shopify has no sandbox endpoint. A blind
   purchase on a connected live store is a real label, charged to the merchant.
3. **Amazon shows Amazon's test orders, not the seller's.** Under sandbox, `AmazonSource`
   searches Amazon's static sandbox cases (the JP marketplace), so a seller's real orders
   never import in Demo.
4. **The demo tenant holds real customers' names and addresses** for as long as the
   connection stays.

Already harmless: pick batches and pack slips never leave PolyBag. Direct-carrier labels
are sandbox specimens. Address validation uses the fake validator under sandbox. Closing
Shipments the source closed changes only PolyBag's own rows. Amazon Buy Shipping and
Amazon exports go to the sandbox host.

## Decisions

1. **In Demo, PolyBag never writes to a Shopify or Amazon store,** with one exception: a
   Shopify Shipping label on a development store (decision 2). It still reads: imports,
   location sync, fulfillment status, and the replacement fulfillment order after a void.
   A Database connection's write-back is not a store and is what `demo:reset` relies on,
   so it is unaffected.
2. **In Demo, Shopify Shipping is offered only on a development store,** decided from the
   store's plan, read live.
3. **Connecting a live store in Demo is allowed.** Reading the prospect's orders is the
   point.
