# Demo reads Amazon orders from production, buys postage from the sandbox

Status: done
Category: enhancement
Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

[PRD](../PRD.md), "What would go wrong today" point 3. Needs `01` first.

## Problem

`AmazonSource` decides everything Amazon does from the one `sandbox_mode` setting: order
search, catalog lookups, marketplace discovery (`AmazonMarketplaceDiscoveryService`),
Buy Shipping, and the shipment confirmation. Under sandbox the order search returns
Amazon's static test cases (JP marketplace) instead of the seller's orders. Demo forces
sandbox on, so a connected seller's real orders never appear.

## Decision

Chosen 2026-10-22. In Demo, Amazon **reads from production and buys postage on the
sandbox**:

| Call | In Demo |
|---|---|
| Orders search, order items, catalog | production |
| Marketplace discovery | production |
| Shipping v2 `getRates`, `purchaseShipment`, `cancelShipment`, documents, tracking | sandbox |
| Shipment confirmation | not sent (`01`) |

The rejected option was to keep Amazon fully sandboxed in Demo and make the live-store
demo Shopify-only. It was rejected because a seller's own orders are the point of the
demo, and the split can be made safe.

### The split lives on the request class

Each SP-API request class declares whether it is a read or postage, and
`AmazonSpApiConnector` picks the host from that, the way `DeclaresSandboxRegion` already
moves a request's sandbox host. The other option, where each call site asks for an
environment, was rejected because every current and future call site would have to
choose, and a wrong choice copied into a new call could send a postage request to
production.

- A **read** request (`SearchOrders`, `SearchCatalogItems`,
  `GetMarketplaceParticipations`, and any other order or catalog read) goes to production
  in Demo.
- A **postage** request (`GetShippingRates`, `PurchaseShipment`,
  `CancelAmazonShipment`, `GetShipmentDocuments`, `GetShipmentTracking`,
  `GetAdditionalInputsSchema`) follows `sandbox_mode` as today, which Demo forces on.
- A request that declares neither follows `sandbox_mode` too, so a new request someone
  forgets to mark fails safe on the sandbox in Demo.
- `ConfirmShipment` is a write to the seller's order, not postage. `01` already stops it
  in Demo, before any connector is built.
- Outside Demo nothing changes: every request follows `sandbox_mode`.

The Amazon Shipping sale to other channels (`AmazonShippingAdapter`) uses the same
postage requests, so it stays on the sandbox with no extra work.

### `AmazonSource`'s own sandbox branches follow the read environment

`AmazonSource` reads `sandbox_mode` in several places that are really asking "are these
Amazon's canned test orders?", not "is postage fake?":

- searching the JP test marketplace, with its fixed `includedData`
- using ordered quantity instead of the quantity left to ship
- skipping the product auto-update from the catalog
- refusing a historical import

In a live-Amazon demo the orders are real, so these key on the environment the read
went to, not on `sandbox_mode`. The same goes for `AmazonMarketplaceDiscoveryService`.
Put the answer in one place, the same one the connector uses, so the import and the host
can never disagree.

### Offers and observed services record the postage environment

`SourceEnvironment` stamps an Offer and an observed service with where it was quoted,
and redemption rejects an Offer whose environment has changed. It stays the postage
environment. In Demo every Amazon quote and purchase is on the sandbox, so the binding
holds whatever host the order was read from. Say this in `SourceEnvironment`'s doc
comment.

### No buyer data is imported in Demo

The order read in Demo keeps only the destination's city, state or region, postal code
and country: no buyer or recipient name, street lines, phone or email. That keeps a
live-Amazon demo within Amazon's Data Protection Policy without making the demo tenant a
PII store, and it shrinks what `04`'s purge has to cover for Amazon.

- In Demo, the order search does not ask for buyer or recipient data beyond what the
  address fields above need. Check what `RECIPIENT` in `includedData` releases without a
  restricted data token, and ask for less if the city, state, postal code and country
  are available another way.
- Whatever Amazon returns, nothing beyond those four fields is written to a Shipment,
  logged, or kept in an error context. Drop the rest as soon as the order is parsed.
- This depends on the mode (Demo), not on the environment.

### The street line

Settled 2026-10-22 by testing against the carrier sandboxes. Demo imports an Amazon order
with `Address withheld` as address line 1, which reads as a placeholder on a pack slip
and a label and could never be mistaken for the buyer's street. Each direct-carrier
sandbox accepts it:

- **USPS** ships it when the label request sets `ignoreBadAddress`. The adapter does not
  send that flag today, so this issue adds it. Send it only in sandbox, and only for a
  withheld address: production must keep refusing a bad address.
- **UPS** already sends `RequestOption: nonvalidate` on the ship request
  (`UpsAdapter`), so it needs nothing.
- **FedEx** rates on a canned origin and destination in sandbox, which answers
  `FEDEX_GROUND`. A label to a residence must be bought as `GROUND_HOME_DELIVERY`, and
  914af49f already offers the sandbox Ground rate to a residential US destination as Home
  Delivery. The label prints the address PolyBag sends, placeholder included. A withheld
  address must still reach the label request as residential, since address validation,
  which usually classifies it, must not run against a placeholder.

Address validation skips a withheld address rather than recording it as undeliverable,
so the Shipment is not marked invalid and held from purchase.

Buy Shipping in Demo offers the Amazon Shipping carrier from the SP-API sandbox, and the
order can also be rated and bought through the USPS, UPS and FedEx sandbox accounts as
direct postage.

### The Ship page says the rates are canned

In Demo, when the Ship page shows Amazon sandbox rates for an Amazon order, it says so:
the sandbox returns fixed offers whatever the order, and the Label is a sandbox specimen.

## Comments

**2026-10-22 — implemented.**

- **The split.** Two marker interfaces in `app/Http/Integrations/Amazon/`:
  `ReadsSellerData` (`SearchOrders`, `SearchCatalogItems`,
  `GetMarketplaceParticipations`) and `PostageRequest` (`GetShippingRates`,
  `PurchaseShipment`, `CancelAmazonShipment`, `GetShipmentDocuments`,
  `GetShipmentTracking`, `GetAdditionalInputsSchema`). `ConfirmShipment` declares neither.
  `AmazonSpApiEnvironment::usesSandbox()` is the one answer: outside Demo it is
  `sandbox_mode`; in Demo a read goes to production and everything else, a request marked
  both included, stays on the sandbox. `AmazonSpApiConnector::boot()` sets every
  request's host from it, then applies `DeclaresSandboxRegion` only to a sandbox request,
  so the order search's Far East sandbox region is not used in Demo. Production stays the
  North America host, which serves every marketplace `AmazonMarketplace` lists. Nothing
  else is sandbox-specific: the LWA token endpoint and the broker refresh are the same in
  both, so a connection's credentials work against production unchanged.
- **One source of truth.** `AmazonSpApiEnvironment::readsFromSandbox()` asks the same
  method about `SearchOrders`. `AmazonSource` keys the JP test search, ordered versus
  remaining quantity, the catalog auto-update and the historical-import refusal on it;
  `AmazonMarketplaceDiscoveryService` and the connection page's historical-import and
  marketplace-refresh actions do too. The export's sandbox payload and context ask
  `usesSandbox(ConfirmShipment::class)`.
- **Offers.** `SourceEnvironment` is unchanged in behavior and documented as the postage
  environment. A Demo test imports an order from the production host, quotes it on the
  sandbox, and buys it: the Offer is stamped Sandbox and redeems.
- **No buyer data.** `AmazonBuyerDataFilter` runs on each page of the order search as
  soon as it is decoded, so the import, its order cache and the closed-order closer never
  hold more. In Demo it drops the buyer block and the delivery preference, keeps only
  city, state or region, postal code and country of the delivery address, and drops item
  gift messages and customizations. `AmazonSource` then writes
  `Shipment::WITHHELD_ADDRESS_LINE` (`Address withheld`) as line 1; name, company, line 2,
  phone, email and the address type stay null. `Shipment::isAddressWithheld()` and
  `AddressData::isWithheld()` recognize it. Keyed on `AppMode::Demo`.
- **`RECIPIENT`.** The v2026-01-01 schema in `tests/Fixtures/Schemas/` puts the delivery
  address only in `recipient.deliveryAddress`, so city, state, postal code and country
  cannot be had without `RECIPIENT`. The same dataset carries the recipient's name,
  company, every street line, phone, address type and delivery instructions, and the
  import reads all of them today with no restricted data token, so `RECIPIENT` releases
  the full address to this app. Settled from the code and schema, with no live call. Demo
  keeps asking for `RECIPIENT` and strips the response; it never asks for `BUYER`, since
  the JP test search that does is not used in Demo.
- **The street line.** A withheld address reaches a carrier as residential, whatever the
  order said, and with the name "Name withheld", never stored. USPS, UPS and FedEx each
  refuse a recipient with no name or company, and a company would make it a business.
  USPS sets `toAddress.ignoreBadAddress` on a domestic label only in sandbox and only for
  a withheld address; the hand-written USPS label schema allows it. UPS sends
  `nonvalidate` and a residential indicator. FedEx rates it residential, so the sandbox
  Ground rate is offered as Home Delivery (914af49f), and the label carries
  `residential: true`. `ShipmentValidationPlan` names no validator for a withheld address,
  so it stays not checked, records no attempt, and is never held.
- **Ship page.** In Demo, rates that include an Amazon Buy Shipping offer show the
  "Amazon sandbox rates" warning on load, the way `02`'s exclusion warning shows.

Tests: `tests/Feature/DemoAmazonReadsProductionTest.php` (host per request class,
enumerating every postage request; an unmarked request; Production and Dev; the Demo
import, catalog, historical import and discovery; buyer data kept out of Shipments and
logs; validation skipped; the Offer redeemed; Amazon Shipping for another channel; the
Ship page note) and `tests/Feature/DemoWithheldAddressLabelTest.php` (USPS
`ignoreBadAddress` and never in production, UPS `nonvalidate`, FedEx Home Delivery to a
residence).

Not checked live. Before the first live-Amazon demo, a person should check that a
production order search in Demo returns the seller's open orders and that the stored
Shipment holds only the four address fields. They should also buy one sandbox Label from
each of USPS, UPS and FedEx for an `Address withheld` Shipment with the "Name withheld"
stand-in, since the 2026-10-22 sandbox runs used a made-up name. A withheld address to
another country is not handled: USPS's international label gets no `ignoreBadAddress`.
