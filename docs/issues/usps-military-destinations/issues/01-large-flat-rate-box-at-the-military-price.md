# Large Flat Rate Box at the military price

## Problem

USPS prices the Large Flat Rate Box lower when it is addressed to an APO/FPO/DPO —
rate indicator `PM`, $29.59 against `PL`'s $31.00 on the sandbox's commercial table.
The `search` endpoint returns `PM` for every destination, so the adapter drops it
outright rather than let it undercut `PL` on domestic addresses. A military large box
therefore pays $1.41 more than it should, on every label.

## Desired behaviour

For a military destination, `PL` and `PM` swap roles: `PM` is kept and classified
`exactly(UspsLargeFlatRateBox)`, and `PL` is dropped, so the shared packaging filter
sees one large-box rate at the right price. For any other destination nothing changes.
The classifier stays exhaustive: `PM` restated for a non-military destination is still
refused, not defaulted.

The destination is already known to the adapter in both places it needs it —
`RateRequest` carries the destination and `ShipRequest` carries the address that
`isMilitary()` reads — so this is a destination rule beside the packaging table, not a
change to the table.

## Recommendation

`ready-for-agent`. The filter and classifier are fixture-tested, and `05`'s fixture
helpers already cover the pairs. The one thing an agent cannot do is prove USPS accepts
a `PM` label to an APO — that is `03`.
