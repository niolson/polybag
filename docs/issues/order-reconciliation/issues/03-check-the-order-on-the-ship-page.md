# Check the order on the Ship page, alongside rate shopping

Status: ready-for-agent
Category: enhancement
Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

[PRD](../PRD.md), decisions 3 and 5. Needs `02`. This is the slice that actually stops a
double shipment; reconciliation only shortens how long a stale Shipment sits.

## Problem

A Shipment from a Shopify or Amazon connection can be fulfilled elsewhere or cancelled
at the source while still `Open` here. The Ship page will buy a Label for it.

## Desired behavior

**An order-status lookup per source.** A small contract (say `OrderStatusLookup`) with
Shopify and Amazon implementations, returning a DTO: `Open`,
`PartiallyFulfilledElsewhere` (with the items the source reports shipped), `Fulfilled`
(with carrier and tracking when given), `FulfilledByPolyBag`, `Cancelled`, or
`Unreachable`. It takes a list of Shipments so `04` can batch it; this slice calls it
with one.

- **Shopify:** the order's `cancelledAt`, `displayFulfillmentStatus` and fulfillments by
  GraphQL, through the connection's `ShopifyConnector`.
- **Amazon:** `getOrder` (Orders v2026-01-01, 0.5/s, burst 30; a new Saloon request
  beside `SearchOrders`), reading `fulfillment.fulfillmentStatus`.
- **PolyBag's own fulfillments** (decision 3) are recognized by the Label's
  `shopify_fulfillment_id`, the Package's `PackageExport` rows, or the tracking number,
  and reported as `FulfilledByPolyBag`, never as fulfilled elsewhere.
- Timeouts, 5xx, throttling and auth failures are `Unreachable`, never an exception that
  stops the page.

**Timing: no added wait.** The lookup goes out in the same concurrent fan-out as the rate
quotes in `ShippingRateService`, so it costs no wall time. The result is stored on the
Shipment (`source_checked_at`, `source_check_result`). At purchase, in the shipping
workflow, a result younger than ten minutes is reused; an older one is repeated first.
Database and manual Shipments skip all of this.

**What the Ship page does with it:**

| Result | Ship page |
|---|---|
| `Open`, `FulfilledByPolyBag` | Nothing shown |
| `Unreachable` | Warning banner; purchase allowed; the Label records `source_verified = false` |
| `PartiallyFulfilledElsewhere` | Purchase refused; lists the items the source shipped; sets `review_reason` |
| `Fulfilled` | Purchase refused. A Manager or Admin is offered *Send a replacement*, confirms it, and the Label records that they did |
| `Cancelled` | Purchase refused, for everyone |

The replacement check is on the role, not `ShipmentPolicy::reship()`, which lets every
user reship an `Open` Shipment (PRD decision 5).

The refusal is enforced in the shipping workflow, not only the page, so a stale Offer
cannot get around it.

## Acceptance criteria

- [ ] `OrderStatusLookup` contract, Shopify and Amazon implementations, result DTO; unit
      tests per result including each `Unreachable` cause
- [ ] Lookup runs in the rate fan-out; result stored on the Shipment; reused at purchase
      under ten minutes, repeated over it
- [ ] Each row of the table above, as feature tests on the Ship page and the workflow
- [ ] A stale `Open` Shipment fulfilled at the source: a shipper is refused, a manager can
      confirm a replacement, and it is recorded
- [ ] An `Unreachable` purchase succeeds and the Label records it was not verified
- [ ] Amazon: `getOrder` request matches the vendored `orders_2026-01-01.json` schema
