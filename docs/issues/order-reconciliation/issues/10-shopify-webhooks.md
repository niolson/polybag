# Shopify webhooks for hosted instances, then slow the backstop poll

Status: needs-triage
Category: enhancement
Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

[PRD](../PRD.md), decision 6. Needs `06`.

## Problem

Polling every fifteen minutes leaves a window in which a cancelled or fulfilled-elsewhere
order looks open. `03` covers the purchase, but the Pack page and lists are stale for
that long.

## Desired behavior

On instances that are publicly reachable, subscribe each Shopify connection to
`orders/cancelled`, `orders/fulfilled`, `orders/partially_fulfilled` and
`fulfillment_orders/*` as needed, verify each delivery's HMAC against the app's client
secret, and run `06`'s reconciliation for that order. On-prem installs that are not
reachable stay on polling. With webhooks in place, the backstop poll runs every hour or
two.

## Open before it is ready

- How an instance knows it is publicly reachable (a setting, or a test delivery).
- Subscription lifecycle: on connect, on reconnect, and removal on disconnect.
- Whether Dev Dashboard apps declare webhook topics in config rather than per shop.
