# Check orders before batch ship and auto-ship, one lookup per connection

Status: wontfix
Category: enhancement
Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

[PRD](../PRD.md), decision 5. Needs `03` (the lookup) and `07` (the Amazon watermark).

## Problem

Batch ship and auto-ship buy Labels with nobody watching. A per-Label `getOrder` would
make Amazon's order lookup the slowest step: 0.5/s with a burst of 30, against 5/s for
rates and purchases, so a 100-order batch would wait about 140 seconds on it.

## Desired behavior

Before buying, group the batch's Shipments by connection and look them up together:

- **Amazon:** one `searchOrders` for `SHIPPED` and `CANCELLED` orders updated since the
  connection's reconciliation watermark (`07`). Any batch order in the result is
  resolved; the rest are `Open`. If `searchOrders` is throttled, fall back to `getOrder`
  for as many orders as its bucket allows, and treat the rest as `Unreachable`. Do not
  advance the watermark from here unless the search covered everything the import's
  would.
- **Shopify:** one `nodes(ids:)` query per 250 orders.

Then, per Package:

- `Open` / `FulfilledByPolyBag`: buy.
- `Unreachable`: buy, and list it in the batch result as not checked; the Label records
  `source_verified = false`.
- `Fulfilled`, `Cancelled`: skip, reported in the batch result by name. Never a
  replacement.
- `PartiallyFulfilledElsewhere`: skip, set `review_reason`.

A Shipment checked by `03` within ten minutes reuses that result.

## Acceptance criteria

- [ ] One Amazon `searchOrders` per connection per batch, not a request per Label (test
      counts requests)
- [ ] Throttled search falls back to `getOrder` within its burst, then `Unreachable`
- [ ] Shopify lookups batched by 250
- [ ] Each result's behavior in batch ship and auto-ship, with the batch result naming
      skipped and unchecked orders
