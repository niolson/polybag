## Problem

A fulfillment order moved whole keeps its ID (`06` comments). Moved to a
location the connection ignores, it is closed as `Cancelled`/`source`
(`ShopifyClosedFulfillmentOrderCloser::report()`). Moved back, the import fetches it open
again at a handled location, and `ShipmentBatchWriter::shouldUpdate()` skips it because
the Shipment is no longer open. The run counts it as skipped and the Shipment stays
`Cancelled`. `08` says an import never reopens a Shipment it cancelled, but there the
advice is to map a reversible hold to `open`; for Shopify, PolyBag itself maps a reversible
location move to `Cancelled`.

## Evidence

Scenario: connection ignores location B. Fulfillment order X (Shipment S,
open, no Package) is moved to B; the next import closes S as `Cancelled`, origin `source`.
The merchant moves X back to location A; every later import returns X as `OPEN` at A and
skips S. S stays `Cancelled` and the order is never packed.

## What to build

Product decision. Either let the writer reopen a Shipment the source
cancelled (origin `source`, no Label, not a manager's) when the source offers it as open
work again, or treat "moved to an ignored location" as no change rather than `Cancelled`.
