# Warn on the Pack page when the order is closed at the source

Status: wontfix
Category: enhancement
Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

[PRD](../PRD.md), decision 5. Needs `03`.

## Problem

The Ship page stops the purchase, but by then the goods have been picked and packed. The
earliest useful moment is when the packer opens the order.

## Desired behavior

Opening Pack for a Shopify or Amazon Shipment starts the `03` lookup without holding up
the page: deferred (`wire:init` or a lazy call after render), never on the request that
renders it. When it comes back `Fulfilled`, `Cancelled` or `PartiallyFulfilledElsewhere`,
a banner says so and names what the source reported. Packing is not blocked; the Ship
page blocks. `Unreachable` shows nothing here.

The result is stored on the Shipment like `03`'s, so the Ship page can reuse it if the
packer moves on within ten minutes.

Watch the Amazon budget: a Pack open is one `getOrder`, and `getOrder` has a burst of
30. Skip the lookup if the Shipment was checked within the last ten minutes.

## Acceptance criteria

- [ ] Page renders without waiting on the lookup (test the render does not call it)
- [ ] Banner for each closed result; nothing for `Open` and `Unreachable`
- [ ] A check under ten minutes old is reused, not repeated
