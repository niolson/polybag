# Print a pack slip for one Shipment and record it on the Shipment

Status: ready-for-agent
Category: enhancement
Created: 2026-09-30

## Parent

[pack-slips PRD](../PRD.md)

## What to build

This is the thinnest end-to-end path: a user prints or views one Shipment's pack slip
from the Shipment's page, and the Shipment records that its slip was printed. It builds
the pieces every later slice reuses.

- **Pack slip renderer.** Moves the rendering and logo resolution out of the pick batch
  controller and the View Pick Batch page into one service. It takes an ordered set of
  Shipments and an optional tote code per Shipment, and returns the HTML view or a PDF
  through the existing PDF renderer. Branding comes from each Shipment's Client, falling
  back to the tenant's pack slip logo. The tote row prints only when a tote code is
  given. Each slip carries the Shipment's PolyBag scan code and its order reference.
- **Schema.** New columns on Shipments: `items_version` (default 0; slice 03 makes it
  move), `pack_slip_items_version`, `pack_slip_receipt_issued_at` (microseconds),
  `pack_slip_printed_at` and `pack_slip_printed_by`.
- **Receipts.** Every rendering comes with a signed, expiring receipt listing each
  Shipment's `items_version`, read before its items are loaded, plus the user and an
  issue time in microseconds.
  - **Redemption only moves forward.** It is one conditional update per Shipment, applied
    only when the receipt's (version, issue time) is newer than what is stored.
  - **What it records:** the version, the issue time, the printed time (now) and the
    user.
  - **What it skips:** Shipments that have shipped or been deleted.
- **Print path.**
  - The report-print code in the QZ Tray component accepts an optional receipt. When QZ
    reports the job sent, it posts the receipt to a new acknowledgment endpoint, the
    same way labels acknowledge a print.
  - **Messages to the user:** "Sent to the printer", with a hint to reprint if no paper
    came out. A failed print says the slip was not recorded. A failed acknowledgment
    offers Mark as printed for the same receipt.
- **Job size limit.** The shared print path owns the limit for every caller. A run of more
  than about 200 slips (exact figure set here) is sent as consecutive QZ jobs of at most
  that size, each with its own receipt, in the run's order. The run stops at the first
  failed job; earlier jobs stay recorded, and the user is told how many were sent and
  where it stopped. Nothing refuses a run for its size. This slice only prints one slip,
  but later slices rely on the path doing this.
- **Browser view.** The HTML view carries its receipt and a Mark as printed control that
  is hidden from print output. Marking as printed redeems that receipt and never records
  against the Shipment's current state.
- **Shipment page.**
  - **Actions:** a Print / Reprint Pack Slip action (through QZ) and a View action.
  - **Display:** when the slip was printed and by whom, and the Shipment's active pick
    batch, if any.
  - **Tote code:** a Shipment in a batch prints without its tote code, and the action
    says so.
  - **Permissions:** available to Shippers (the `User` role).
- Add **pack slip** to `CONTEXT.md` as the name for this document, and define "printed"
  as sent to the printer.

## Acceptance criteria

- [x] A Shipper can print a Shipment's pack slip from its page. After QZ reports the job
      sent, the Shipment shows it as printed, with the time and the user.
- [x] A failed QZ print records nothing and tells the user.
- [x] Viewing the slip and using Mark as printed records it against the viewed receipt.
- [x] A tampered, expired or other-user receipt is refused.
- [x] Redeeming a receipt twice changes nothing. Redeeming an older receipt after a newer
      one leaves the newer print and its user in place.
- [x] A Shipment shipped between rendering and redemption is skipped.
- [x] A slip is branded from its Shipment's Client, and falls back to the tenant logo.
- [x] A slip has the tote row only when a tote code is given, and always shows the scan
      code and reference.
- [x] A batched Shipment's page reprint says the tote code is omitted.
- [x] The existing pick batch pack slips still render through the new renderer, with no
      visible change.
- [x] The print path splits a run over the limit into jobs of at most that size, each
      with its own receipt, and stops at the first failure with earlier jobs recorded.
      This is tested at the service level with a run just over the limit.
- [x] `CONTEXT.md` defines pack slip.
- [ ] Manual check at review: a real QZ Tray print acknowledges, and a disconnected QZ
      Tray does not.

## Comments

- 2026-10-03 — Implemented on branch `pack-slips-01`; awaiting the manual QZ Tray check.
  Decisions made while building it:
  - One QZ job holds at most 200 slips (`PackSlipRenderer::SLIPS_PER_PRINT_JOB`).
  - A receipt is sealed with `Crypt` (the app key), not a signed URL, and lives 24 hours
    (`PackSlipReceipts::LIFETIME_SECONDS`) so a view left open across a shift can still be
    marked printed.
  - The user column is `pack_slip_printed_by_user_id`, matching the repo's other
    `*_by_user_id` foreign keys, rather than the PRD's `pack_slip_printed_by`.
  - Redemption records only on an open Shipment, which skips void Shipments as well as
    shipped ones. A receipt replaces a stored print of the same version that has no issue
    time, which is what slice 02's migration writes.
  - The queue index in the PRD's schema is left to slice 04, where its query is written.
  - Print-mode batch slips used to be drawn without the batch's Client, so they lost the
    return address and footer. The renderer now brands each slip from its own Shipment's
    Client, which fixes this.
  - The pick batch's browser view already carries a receipt and Mark as printed, since
    every view the renderer draws does. The batch's print mode still records on batch
    membership until slice 02.
- 2026-10-03 — Pack slips print on the image label printer with a 4x6 page. Since the 4x6
  redesign in May (`21f6233`), they had gone to the document printer with a letter page
  and been scaled up. There is no setting, because there is only the 4x6 layout. The
  batch's Pack Slips button now uses the same receipt-carrying path; it still also marks
  batch membership printed on render until slice 02.
