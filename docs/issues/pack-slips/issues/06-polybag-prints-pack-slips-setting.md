# "PolyBag prints pack slips" setting

## What to build

This setting is for a tenant whose ERP prints its own pack slips: PolyBag then shows no
pack slip screens or indicators.

- **New setting.** `pack_slips_enabled` is a tenant-wide setting, on by default for new
  and existing installs, in the same Settings section as picking.
- **Relabel picking.** `picking_enabled` is relabelled "PolyBag prints pick batches".
  "Require picking before shipping" stays nested under it, and its help text says pack
  slips then print from pick batches.
- **When it is off, these are hidden:**
  - the Print Pack Slips page and its navigation entry
  - the pack slip and Print Both buttons on View Pick Batch, leaving the Picking Summary
  - the "Slip Printed" and "Slip Printed At" columns in the batch's Shipments table
  - the Print / View Pack Slip actions and printed details on the Shipment page
  - the Shipments list column and filter
  - the Scan & Pack out-of-date warning
- **When it is off, these stay:** the pack slip branding fields in Settings and on
  Clients stay, shown as inactive with a note, so turning the setting back on loses
  nothing.
- **Scan & Pack is unchanged.** It still opens Shipments by PolyBag scan code or by exact
  `shipment_reference`.

## Acceptance criteria

- [ ] The setting defaults to on, and existing installs keep it on.
- [ ] With it off, each hidden element listed above is absent, and the page's route
      refuses access.
- [ ] With it off and picking on, View Pick Batch offers only the Picking Summary, and its
      Shipments table has no Slip Printed columns.
- [ ] The branding fields keep their values across off and on.
- [ ] With it off, scanning a value that exactly matches an imported
      `shipment_reference` opens that Shipment at Scan & Pack. This is the ERP
      workflow.
