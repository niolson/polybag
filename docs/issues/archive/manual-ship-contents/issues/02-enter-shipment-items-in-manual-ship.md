# Enter Shipment items in Manual Ship

Status: done
Category: enhancement
Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

`manual-ship-contents`. Separate from `01` (Product value), which it can use but does not
need.

## Problem

Manual Ship takes an address and a parcel but no contents. Without scan-to-add, the Draft
Shipment it buys from has no items and no value, so an international Manual Ship has
nothing to put on a customs form. With scan-to-add, the contents are only what can be
scanned, so an item with no Product (a sample, a replacement part) cannot be entered.

A Shipment's items can already be added, edited and deleted afterwards in the Shipment
resource's items relation manager (`ShipmentItemsRelationManager`), but not in the Manual
Ship flow. Editing items there on an imported Shipment also has no guard: the next
`update` import from the source rewrites them.

## Proposal

- Optionally, behind a setting, let Manual Ship take items: a repeater of description,
  SKU, quantity, unit value, weight, HS code and country of origin. Each line may be
  picked from the Product catalog to prefill it, or typed freehand. Show the Shipment's
  currency beside the values.
- Sum the lines into the Shipment's `value` unless one is entered.

## Triage (2026-11-02)

- **Manual Ship only.** Typed-in items become real ShipmentItems on a Shipment PolyBag
  owns (no source to overwrite them). Values are in the Shipment's currency, the Client's
  (`01`). A line picked from the catalog prefills its value from the Product's customs
  value.
- **Packing validation counts them.** They are the Shipment's expected contents, so
  Pack checks them like an imported order's items.
- **Imported Shipments are not edited here.** The source owns their items: a Shopify
  order edit or an ERP correction arrives through the next import, and an edit made in
  PolyBag would be overwritten by it and leave a printed pack slip out of date. Guard
  `ShipmentItemsRelationManager` on a Shipment with a source: read-only, or a warning that
  the next import replaces the change. Decide which when building it.
- **Pack-time substitutions are out of scope.** No one needs them yet. If they come up,
  they are a Package-level difference from the Shipment, which `01`'s package item
  `value` begins to model.
- **Who may enter items** follows `warehouse-permissions/01` for Manual Ship; nothing
  separate here.

## Built (2026-11-03)

- **A typed-in item becomes a catalog Product.** `shipment_items.product_id` and
  `package_items.product_id` are required, and customs, `CustomsReadiness`, Pack, pack
  slips, pick lists, weight checks and rules all read the item's Product. A typed-in line
  makes one in the Client's catalog, as an import does for an unseen SKU, so it needs a
  SKU. A SKU already in the catalog is refused, never reused or overwritten: pick it
  instead. A catalog line declares its Product's details; only its quantity and value are
  its own (`ManualShipContents`).
- **The Shipment's value** is the one entered, with or without items, else the items'
  total. It stays unknown (null) when any item has no value, rather than understating it.
- **Ship and Auto Ship** put every item in the Package at its full quantity, since no one
  scans them after. **Pack** starts with an empty Package Draft and checks the items, with
  scan-to-add off because the Shipment has items.
- **Relation manager: read-only**, not a warning, while the Shipment's source imports
  items (`ShipmentItemImporter::isEnabledFor`). A warned edit would still save and then be
  overwritten. A source with item import off, or no source, stays editable.

## Acceptance criteria

- [x] With the setting on, Manual Ship can record items, freehand or from a Product
- [x] The Draft Shipment and the bought Label's customs lines carry those items and values
- [x] Pack validates the packed items against them
- [x] Items on a Shipment with a source cannot be silently edited in the Shipment resource
- [x] With the setting off, Manual Ship behaves as it does today
