# Capacity audit

Status: reference
Created: 2026-10-24

## Goal

Know, with measured numbers, how big each workload can get before it fails, and make
each limit deliberate: either a cap the UI enforces and explains, or a design whose
cost does not grow with the workload.

This started from [`import-memory/01`](../import-memory/issues/01-shopify-import-exhausts-the-worker-memory-limit.md).
A Shopify import of about 5,000 open fulfillment orders died on PHP's default 128M
limit, with no error in the app. Nothing had measured how much memory an import
needed, and nothing in development could show it: local CLI PHP runs with
`memory_limit = -1`.

## What a finding records

For each workload:

- **The size axis.** What grows: open orders, Shipments in a batch, slips in a run,
  people packing at once.
- **Measured cost at several sizes.** Peak memory, wall time, and requests or jobs,
  at roughly 1×, 10× and 100× of a typical day, under the limits a deployed instance
  actually runs with. Record the numbers in the issue file and keep the raw captures
  in `.scratch/capacity-audit/`.
- **Where it fails, and how.** An exception that reaches the user, a fatal error the
  app never sees ([`import-memory/02`](../import-memory/issues/02-a-queued-job-that-dies-says-so.md)),
  an HTTP timeout, or requests queuing.
- **The decision.** Either a cap enforced in the UI with a message, or a change so the
  cost stops growing with the workload, as `import-memory/01`'s two-pass read does.

## Limits a deployed instance runs with

As shipped in the `Dockerfile` and `docker-compose.yml`, checked 2026-10-24:

| Limit | Value | Where it comes from |
|---|---|---|
| PHP `memory_limit` | 128M | The `php` image default. Nothing raises it |
| Import run memory | 256M | `SHIPMENT_IMPORT_MEMORY_LIMIT`, applied by `ShipmentImportService::import()` |
| php-fpm workers | `pm = dynamic`, `pm.max_children = 5` | The `php-fpm` image's `www.conf` default. Nothing overrides it |
| `queue` workers | 1 process, `default,low` | `docker-compose.yml` |
| `import-queue` workers | 1 process, `imports` | `docker-compose.yml` |
| `imports` `retry_after` | 1,860 s | `config/queue.php` |

## Out of scope

- Hosting capacity of the servers we operate (CPU, RAM per tenant). Those decisions
  are tracked privately. This audit is about what one instance's code and default
  configuration can carry.
- Carrier API rate limits, except where they set a workload's wall time.
