# Import marketplace cancellations, so a cancelled order is neither shipped nor kept

Status: needs-triage
Category: bug
Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

Split out of [`02`](02-purge-skips-company-only-void-and-partly-shipped.md). `02` purges a
`void` Shipment once it is past retention, but nothing makes a cancelled marketplace order
`void`, so a cancelled order never reaches that clock.

## Problem

No import path sets `ShipmentStatus::Void`. Only a person does, through the Shipment form.

- **Amazon.** `AmazonSource::fetchShipments()` asks for
  `fulfillmentStatuses: UNSHIPPED,PARTIALLY_SHIPPED`. When Amazon or the buyer cancels an
  order, it drops out of that filter and is never fetched again, so its Shipment stays
  `open`.
- **Shopify.** `ShopifySource` reads `fulfillmentOrders(includeClosed: false)`. A cancelled
  order's fulfillment orders close, so they drop out the same way.

That costs two things:

1. **Cancelled orders get shipped.** A cancelled order still appears as open work: it can
   be picked, packed, labelled and batch shipped. A buyer can cancel too, not only Amazon,
   so this happens in the normal course of business, not just with stale orders. Nothing
   stops a `void` Shipment from being packed either: `Pack` only warns about `shipped`, and
   `BatchLabelService` only skips `shipped`.
2. **Cancelled orders keep their PII.** Amazon's data protection policy allows PII to be kept
   "no longer than 30 days after order delivery" and only as long as necessary to fulfill
   the order, handle tax, or meet a legal requirement. A cancelled order has no fulfillment
   purpose left, yet its recipient name, address and phone stay in PolyBag indefinitely.

Amazon cancels an unshipped order about seven days after its ship-by date, and some orders
are reported to wait up to 30 days. Either way, an Amazon order still `open` well past its
ship-by date is a state that should not exist here. It means PolyBag missed the
cancellation.

## Proposed decisions

Each one needs a maintainer to confirm it:

- **Amazon: fetch the cancellations.** Add `CANCELLED` to the regular import's
  `fulfillmentStatuses`. `lastUpdatedAfter` already counts a status change as an update,
  so a cancellation inside the lookback window is returned. A `CANCELLED` order that
  matches an `open` Shipment makes it `void`. One that matches nothing is not imported,
  since there is nothing to create.
- **Amazon: check the ones the window missed.** An `open` Amazon Shipment more than
  seven days past `metadata.amazon_ship_by_window.latestDateTime` is looked up by order ID
  on a schedule, and voided if Amazon reports `CANCELLED`. This catches cancellations that
  fell outside the lookback window while imports were paused or failing.
- **Amazon: surface buyer cancellation requests.** Request `CANCELLATION` in
  `includedData`. An item with `cancellation.cancellationRequest.requester: BUYER` on a
  still-unshipped order means the buyer asked to cancel and the seller has to act. Show it
  on the Shipment, warn on Pack and Ship, and skip it in batch ship. Do not void it
  automatically: the seller decides.
- **Shopify: fetch the cancellations.** Detect cancelled orders (the order's `cancelledAt`,
  or fulfillment orders that closed because of a cancellation) and void the matching `open`
  Shipments. *Verify* which query returns them without pulling every closed fulfillment
  order in the store.
- **Only an `open` Shipment becomes `void`.** A `shipped` Shipment is left alone, even if
  the marketplace reports it cancelled. If it has an unshipped Package with an active
  Label (bought, not yet shipped), warn rather than void the Label automatically.
- **Refuse `void` Shipments for fulfillment work.** Pack refuses, or at least warns as
  loudly as it does for `shipped`. Ship and batch ship refuse to buy a Label. Pick batch
  generation already selects only `open` Shipments.
- **Record when a Shipment became void.** Add `shipments.voided_at`, set whenever status
  becomes `void`, whether by import or by hand. `02` can then count from it instead of from
  `updated_at`.

## Acceptance criteria

- [ ] An Amazon order that becomes `CANCELLED` within the lookback window voids its `open`
      Shipment on the next import, and sets `voided_at`
- [ ] An `open` Amazon Shipment past its ship-by date plus seven days is checked by order ID
      and voided if Amazon reports it cancelled
- [ ] A buyer cancellation request is shown on the Shipment, warned about on Pack and Ship,
      and skipped by batch ship; the Shipment stays `open`
- [ ] A cancelled Shopify order voids its `open` Shipment on the next import
- [ ] A `shipped` Shipment is never voided by an import
- [ ] Ship and batch ship refuse to buy a Label for a `void` Shipment
- [ ] Setting status to `void` by hand also sets `voided_at`

## Out of scope

- The Database driver. It has no cancellation signal today; a tenant who needs one can
  map a status column later
- Voiding a bought Label because its order was cancelled. That stays a person's decision
- Finding old `open` Shipments in general: [`04`](04-find-old-open-shipments.md)
