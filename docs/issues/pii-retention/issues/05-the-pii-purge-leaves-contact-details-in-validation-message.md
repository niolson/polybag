## Problem

`ShipmentRowPreparer` writes the unparsed phone number
(`app/Services/ShipmentImport/ShipmentRowPreparer.php:49`) and a rejected email address
(`:281`) into the warnings that become `shipments.validation_message`, and
`ShipmentBatchWriter` keeps them on re-import (`withWarnings()`). `PurgePiiCommand::purge()`
nulls only `Shipment::PII_FIELDS` (`app/Models/Shipment.php:92-111`), which does not list
`validation_message`, so the phone and email the purge removes from `phone` and `email`
survive in the message.

## Evidence

```php
<?php

use App\Models\Package;
use App\Models\Shipment;

it('purges the phone number and email the import wrote into the validation message', function (): void {
    $shipment = Shipment::factory()->shipped()->create([
        'channel_id' => null,
        'validation_message' => 'Invalid phone number could not be normalized: 555-0100 ext 9; Invalid email removed: someone@example',
    ]);

    Package::factory()->shipped()->create([
        'shipment_id' => $shipment->id,
        'shipped_at' => now()->subDays(120),
    ]);

    $this->artisan('shipments:purge-pii')->assertSuccessful();

    $shipment->refresh();

    expect($shipment->first_name)->toBeNull()
        ->and($shipment->validation_message)->not->toContain('555-0100')
        ->and($shipment->validation_message)->not->toContain('someone@example');
});
```

## What to build

Stop echoing the value in the warning ("Phone number could not be
normalized", "Invalid email removed"), as the customs warnings already avoid repeating a
tax ID, and have the purge null `validation_message` (or add it to `PII_FIELDS`) for rows
already written.
