## Problem

UPS and FedEx scrub the recipient tax ID and the EIN from every error log line
and failure message (`scrubCustomsIds()`), because a carrier can echo a rejected value in
free text that key-based redaction cannot see (`international-customs-terms/06` and `07` comments). `UspsAdapter`
logs the decoded error `body` and builds the failure message from `error.errors[].detail`
(`createInternationalShipment()`, lines 1112–1120; `describeLabelError()`) with no such
scrub. `PiiRedactor` redacts `importersReference` by key, which covers the request log but
not a value quoted inside a `detail` string.

## Evidence

Scenario: a Brazil label whose `importersReference.reference` USPS rejects with
a `detail` that quotes the value. The `usps-validation` log and the Offer's
`purchase_failure_reason` then hold the CPF. Not observed: no TEM capture shows USPS quoting
a reference value.

## What to build

Apply the same whole-token scrub to the USPS international error log and
failure message, with a test that a 400 echoing the CPF is redacted.
