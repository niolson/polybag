# Look up a scan as an external identifier, even when it begins with the prefix

Status: wontfix
Category: enhancement
Created: 2026-09-29

## Problem

ADR-0007 gives PolyBag codes precedence: any scan beginning with the install's
`SCAN_CODE_PREFIX` (default `PB`) is parsed as a PolyBag code and never looked up as an
order reference, box alias, SKU or UPC. That keeps a pack slip from opening a different
Shipment, but an external identifier that happens to begin with the prefix can no longer
be scanned:

- An order reference such as `PB1001` cannot be opened from Scan & Pack.
- A product whose only identifier is a SKU beginning with `PB` cannot be packed by scan.

The workaround is the Shipments list search, which is not intercepted, and packing such a
product some other way.

## Proposed behavior

An explicit, one-shot "next scan as text" mode on Scan & Pack:

- A command barcode `PBCLOOKUP` (a new `ScanCommand`, printed on the command sheet) and a
  button beside the scan box both arm it.
- While armed, a badge says so. The next scan skips PolyBag parsing and is handled as an
  external identifier in the current context: an order reference when nothing is loaded
  (with the chooser when several Shipments share it), a box alias or product while packing.
- The mode disarms after that one scan, and on *Clear Shipment*.

Global search keeps no escape of its own; the list pages' searches are the way out.

## Open questions

- Command barcode, button, or both? Both is proposed, so the flow stays scanner-only.
- Should the Ship page's page-wide listener honor it? It only knows `SHIP` today.

## Acceptance

- [ ] `PBCLOOKUP` and the button arm the mode; the next scan is looked up as text; the
      mode then disarms.
- [ ] A `PB…` order reference opens its Shipment (or the chooser) when armed.
- [ ] A `PB…` SKU is packed when armed.
- [ ] ADR-0007's interim-limitation paragraph is removed when this ships.

## Comments

### 2026-10-06 — wontfix

Closed without building. `SCAN_CODE_PREFIX` is set per install, so an install whose order
references or SKUs begin with `PB` chooses a different prefix when it is set up
(`docs/self-hosting.md`, "Barcode prefix"; `03` checks for collisions). An existing
install that finds one changes the prefix and reprints, which costs a few days of
reprinting rather than a permanent mode on Scan & Pack. Reopen if an install's identifiers
leave no prefix free, which is unlikely with four characters to choose from.
