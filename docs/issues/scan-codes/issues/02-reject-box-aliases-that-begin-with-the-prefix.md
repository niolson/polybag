# Reject box aliases that begin with the scan-code prefix

Status: ready-for-agent
Category: enhancement
Created: 2026-09-29

## Problem

ADR-0007 decision 6: a Box Size's operator-chosen code (its alias, `box_sizes.code`) that
begins with the install's `SCAN_CODE_PREFIX` is read by Scan & Pack as a PolyBag code, so
the box can never be scanned by that alias. Nothing stops an operator creating one.

## Work

- Validate `code` on the Box Size form (and the Setup Wizard's box step) against
  `ScanCode::prefix()`, case-insensitively, with a message naming the prefix.
- Surface existing conflicts: the Box Sizes list, or `03`'s check command, names any
  alias that already begins with the prefix, since changing the prefix can create them.
- The seeded aliases (`01`–`27`) begin with digits and cannot conflict with a
  letter-first prefix.

## Acceptance

- [ ] Creating or editing a box with alias `PB12` (default prefix) fails validation;
      `pb12` too.
- [ ] Other letter-and-digit aliases (`A1`, `S12`) are still accepted.
- [ ] A test covers a non-default prefix.
