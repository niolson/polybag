# Check existing identifiers against a proposed scan-code prefix

Status: ready-for-agent
Category: enhancement
Created: 2026-09-29

## Problem

ADR-0007 lets each install set `SCAN_CODE_PREFIX` (default `PB`), because whether a prefix
clashes depends on that install's SKUs and references. Nothing tells an operator whether
it does. Changing the prefix later invalidates every pack slip, command sheet and box
sheet already printed, so it should be chosen once, after looking.

## Work

An artisan command, e.g. `php artisan scan-codes:check {prefix?}` (defaulting to the
configured prefix), that validates the prefix's shape and counts, with a few examples of
each:

- box aliases (`box_sizes.code`)
- product SKUs and barcodes
- order references (`shipments.shipment_reference`), open Shipments first

that begin with it, case-insensitively. Exit non-zero when anything matches, so it can be
run by the on-prem installer before writing `.env`. Mention it in `docs/self-hosting.md`
beside the variable.

## Acceptance

- [ ] Reports matches per kind with counts and examples; exits 0 when there are none.
- [ ] Refuses a malformed prefix with the same rule as `ScanCode::prefix()`.
- [ ] Documented in `docs/self-hosting.md`.
