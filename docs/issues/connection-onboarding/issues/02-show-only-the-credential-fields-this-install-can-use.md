# Show only the credential fields this install can use

Status: ready-for-agent
Category: enhancement
Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

[PRD](../PRD.md), decisions 2 and 3. Needs `01` for `AppMode`.

## Problem

The connection and carrier account forms show every credential field in every mode:

- **Shopify connection:** App Client ID and App Client Secret, which only matter without
  the broker.
- **Amazon connection:** Refresh Token, App Client ID and App Client Secret, likewise.
- **USPS, UPS, FedEx accounts:** an "Advanced / API App Credentials" section, likewise.
- **FedEx account:** both Production and Sandbox account numbers, and both production and
  sandbox API key/secret pairs, although production never uses sandbox and demo never uses
  production.

An operator on a hosted production tenant sees fields that do nothing there, and can
fill one in and route around OAuth by accident.

## Desired behavior

**With the broker configured, in Production and Demo,** these are hidden:

- Shopify: `settings.client_id`, `settings.client_secret`
- Amazon: `settings.refresh_token`, `settings.client_id`, `settings.client_secret`
- USPS, UPS, FedEx: the "Advanced / API App Credentials" section

**Sandbox and production FedEx fields, by mode:**

- Production hides `fedex_sandbox_account_number`, `fedex_adv_sandbox_api_key` and
  `fedex_adv_sandbox_api_secret`.
- Demo hides `fedex_production_account_number`, `fedex_adv_api_key` and
  `fedex_adv_api_secret`.
- Dev shows both.

**Unchanged:**

- Dev shows every field, broker or not.
- With no broker, client credential fields show in every mode. That is how a self-hosted
  install connects.
- A carrier with no OAuth or broker path always shows its client credential fields. Ask
  the carrier, not the mode: something like
  `CarrierRegistry::connectsThroughBroker(string $carrierName): bool`, true today for
  USPS, UPS and FedEx. A future OnTrac returns false and keeps its fields in production.

A hidden field is not dehydrated, so a hidden secret that is already stored is kept, not
cleared.

## Notes

- Amazon's Refresh Token is `required` only when there is no broker on create. That
  rule already lines up with when the field is hidden; keep it that way.
- The Amazon refresh-token helper text ("Otherwise save the connection and use Connect
  Amazon.") changes with `03`.
- **Check before hiding in Demo:** confirm the broker serves sandbox credentials for USPS
  and UPS OAuth, and the FedEx registration proxy for the sandbox. If one does not, its
  app credential section must stay visible in Demo.
- No live tenants, so a production record that already holds direct credentials needs no
  migration. Its stored secrets keep working while hidden.
