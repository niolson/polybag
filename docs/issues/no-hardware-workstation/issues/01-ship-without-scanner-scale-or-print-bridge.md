# Ship an order from a workstation with no scanner, scale or print bridge

Status: needs-triage
Category: enhancement
Repo: `polybag`

> *This was generated by AI during triage.*

## Problem

Pack and Ship assume a warehouse workstation with a barcode scanner, a scale, a label
printer and QZ Tray. Some people who would want to ship an order have none of these:

- **Customer service or another department** shipping one order from an office PC: a
  replacement, a forgotten item, a VIP order.
- **Someone evaluating PolyBag** before buying hardware.

Manual Ship already covers part of this, but only for one-off parcels. These people need
to ship an existing order through Pack and Ship, so its items, Label history and export
stay on that Shipment.

## What already works without hardware

As of commit `eb709fea`:

- **Weight and dimensions can be typed.** They are plain number inputs on Pack
  (`pack.blade.php`, the *Package Measurements* fieldset). Weight starts blank, not zero.
  The minimum-weight substitution (`usesMinimumWeight()`) applies only when a connected
  scale has reported a steady zero, never to a typed or cleared weight.
- **A box is optional.** `box_size_id` is nullable, and `isReadyToShip()` checks only that
  weight and the three dimensions are positive. A Package can be bought with typed
  dimensions and no BoxSize.
- **A scanner is only a keyboard.** Typing a SKU, a barcode or `%B17` into the scan field
  and pressing Enter does what a scan does. Nobody would discover it.
- **A letter-paper label path exists**, but only through QZ: a `print-label` event with
  `orientation: 'report'` goes to the document printer (`qz-tray.blade.php`). The FedEx
  reference test cases use it for `PAPER_85X11_*` stock.
- **Pack slips** already open in the browser (`/shipments/{shipment}/pack-slip`).

## What's missing

### 1. Packing items by hand

In normal mode, an item row has only an *unpack* button. Without scanning, the only way
to pack a line is the `NEXT` command (`ScanCommand::NextItem`), which is not available in
production (`AppMode::Production`).

- Rows need a "pack one" button, and probably a "pack all".
- Typing in items skips the check that the right item went in the box. That's acceptable
  for this case, but it belongs to a deliberate workstation mode, not the warehouse
  default.
- **Transparency items** can't be packed this way: their codes are 2D and can't
  reasonably be typed. The mode has to either refuse a Shipment with Transparency items
  or say plainly that it needs a scanner.

### 2. Choosing a box

Today a box is chosen only by scanning its `%B` code. The fix is a picker next to the
scan field that does what `scanBox(id)` does, listing the same active boxes the barcode
sheet does. This is small.

### 3. Printing without QZ

This is most of the work.

- **Format.** Without QZ there is no raw printing, so the purchase format must be PDF or
  an image. The direct adapters ask for 4×6 today: USPS `labelType: 4X6LABEL` PDF, FedEx
  `STOCK_4X6` PDF, UPS GIF. Amazon and Shopify decide their own format, and Shopify
  reports it rather than taking a request.
- **Print acknowledgment.** Pack and Ship record a print (`last_printed_at`, via
  `POST /labels/{package}/printed`) only after QZ accepts the job, then follow
  `redirectTo`. An OS print dialog reports nothing. This mode needs either a "label
  opened" state that is distinct from printed, or a "Did it print?" confirmation. The
  redirect has to wait for the person either way, or the page they need to reprint from
  is gone.
- **Auto Ship** buys and prints in one step and refuses when the OS reports the label
  printer offline. It has to be off in this mode.
- **Customs forms** follow the label on international Shipments (`printCustomsForm`).
  They need the same fallback, ideally merged into one PDF with the label so a single
  print dialog covers both.
- **Other QZ prints.** Batch Ship, pick lists, End of Day manifests and pack-slip print
  runs all print through QZ. These are out of scope here (see *Out of scope*).

### 4. QZ noise

Pages that expect QZ keep trying to connect and showing errors about the bridge, the
printers and the scale. In this mode they should stay quiet.

## Letter paper: options

A label on 8.5×11 paper can be made several ways. **Gotenberg is not recommended.**
Chromium does not reliably render a PDF embedded in HTML, and it would add a server round
trip to wrap a document we already have.

| Option | How | Cost |
|---|---|---|
| Browser PDF viewer | Open the 4×6 PDF in a new tab; the person prints it at "Actual size" and the viewer centers it on the page | None. Enough for an evaluation |
| Image in a page | Put a PNG or GIF label in a small HTML page sized `4in × 6in` with print CSS | Small; covers UPS GIF cleanly |
| Carrier letter stock | Ask the carrier for letter stock in this mode. FedEx has `PAPER_85X11_TOP_HALF_LABEL`; UPS and USPS options are **unverified** | One stock option per adapter; best output |
| Server-side imposition | Place the 4×6 PDF on a letter page in PHP | Needs a new dependency (e.g. FPDI), which needs approval |

## Proposed decisions

Each one needs a maintainer to confirm it:

1. **An explicit workstation mode, not an automatic fallback.** A "Browser printing (no
   print bridge)" setting in Device Settings, stored in `localStorage` with the other
   printer settings. Falling back silently when QZ can't be reached would hide real
   printer failures from the warehouse, and the Label would already be bought.
2. **Separately, an "Open label" button when a QZ print fails.** This is useful in every
   mode: today a bought label that didn't print leaves the packer with only a banner.
3. **In this mode:** the purchase format is forced to PDF or image, Auto Ship is off and
   hidden, labels open in a new tab, the page asks "Did it print?" before redirecting,
   and QZ connection and printer warnings are suppressed.
4. **Pack in this mode** shows a box picker and per-row pack buttons, and refuses
   Transparency items with a message that names the reason.
5. **Letter paper:** start with the browser PDF viewer and the image page. Add carrier
   letter stock per adapter later, once each carrier's option is verified.

## Rough slices

1. **Small:** the workstation setting, forced format, Auto Ship off, labels in a new tab
   with the confirmation, the box picker and the pack buttons. This covers an evaluation
   and a single customer service order.
2. **Medium:** the "Open label" button on a failed QZ print, customs forms merged into the
   label PDF, and carrier letter stock per adapter.
3. **Later:** browser fallbacks for Batch Ship, pick lists and manifests.

## Out of scope

- Batch Ship, pick batches and End of Day in this mode. Until slice 3, those pages should
  say they need the print bridge rather than fail.
- Reading a scale without WebHID or QZ.

## Questions

- Who may use this mode? A per-workstation setting can be turned on by anyone at that
  workstation. Is that acceptable, or should it also be limited by role?
- Should a Shipment with Transparency items be refused outright, or offer typed codes?
- Is "opened" enough, or does an unconfirmed print need to show up somewhere, such as the
  Package or the exceptions widget?
