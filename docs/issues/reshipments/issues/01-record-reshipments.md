# Record reshipments: why a shipped order was sent again, and what it cost

Status: needs-triage
Category: enhancement
Created: 2026-09-29

## Problem

An order sometimes has to be sent again after it has shipped: the parcel was lost in
transit or arrived damaged, the wrong item was sent, an item was missing, or the carrier
returned it as undeliverable. Each of these is a **reshipment**, and each spends postage a
second time on the same order.

Today a reshipment is just another Package on a Shipment that already shipped. Nothing
records that it is one, why it was sent, or which Package it replaces. So the second
postage spend is invisible. Reports cannot separate it from ordinary volume, a 3PL
cannot bill it back to the client or claim it from the carrier, and nobody can see
whether one client, carrier, or packer causes most of them.

## Current state

- A Package for a Shipment whose status is `shipped` needs a Manager or Admin:
  `ShipmentPolicy::reship`. The Pack page turns a shipper away on mount and rechecks
  before saving progress or buying. The Ship page enforces the same rule through
  `PackagePolicy::ship`, both on mount and again before buying.
- A manager packing a shipped Shipment sees an "Already Shipped" warning, and nothing
  else changes: the new Package is recorded like any other.
- Packing validation compares a Package's items with the Shipment's **full** quantities
  (`EloquentPackageDraftWorkflow::hasCompletePackedItems()`). A reshipment of one wrong
  or missing item therefore fails validation unless validation is turned off. Today the
  only way to reship part of an order is to pack everything, or to disable packing
  validation for the whole site.

## Proposed direction

- **Mark the Package as a reshipment** with a required reason: lost in transit, damaged,
  wrong item sent, item missing, returned undeliverable, customer request, or other
  (with a note).
- **Link it to the Package it replaces**, where there is one. A reshipment for a missing
  item may replace nothing.
- **Start it from the original Package.** A "Reship" action on View Package for a
  shipped Package: the manager picks the reason and the items to send again, and lands
  on the Pack page with a Package Draft that has only those items expected. Reshipping
  from the Pack page after the "Already Shipped" warning should reach the same place,
  asking for the reason first.
- **Validate against what is being reshipped**, not against the full order, so a
  partial reshipment can be packed with validation on.
- **Keep reshipments attended.** They are excluded from batch ship. Whether auto-ship
  may buy one once the manager has started it is an open question below.
- **Report the spend.** Postage on reshipments by client, reason, carrier, and period,
  with the linked original Package's cost beside it.

## Open questions

1. **Billing.** Is reshipment postage billed to the client by default, per reason
   (wrong item sent is the warehouse's fault; lost in transit may be the carrier's), or
   decided per reshipment?
2. **Carrier claims.** Should a reshipment for lost or damaged goods record a claim
   reference and outcome, or is that a separate feature?
3. **Marketplace sync.** What happens to a reshipment's tracking number for Shopify and
   Amazon orders? A second fulfillment, an update to the first, or nothing? Amazon may
   refuse a second shipment confirmation for an order it considers shipped, and Buy
   Shipping postage for such an order may not be offered at all.
4. **Export.** Should database export destinations receive reshipment Packages, and
   flagged how?
5. **Shipment status.** `Shipment::updateShippedStatus()` adds up packed quantities
   across all shipped Packages, so a reshipment inflates them. That is harmless while the
   status is already `shipped`, but a report of "items shipped" would double-count.
6. **Auto-ship.** May a manager's reshipment be bought unattended by rule, or is a
   person always choosing the rate, given that it is a second spend?
7. **Voided reshipment.** If the original parcel turns up before the reshipment ships,
   voiding the reshipment's Label should return it to a Package Draft still marked as a
   reshipment. Or should the reshipment be abandoned entirely?
