# The Amazon import holds every order at once

Status: needs-triage
Category: performance
Created: 2026-10-24

## Problem

`AmazonSource::fetchShipments()` has the same shape as the Shopify read in
[`import-memory/01`](../../archive/import-memory/issues/01-shopify-import-exhausts-the-worker-memory-limit.md).
It pages through orders by `nextToken`, keeps every mapped row, and stores each raw
order in `orderCache` for `fetchShipmentItems()`. Peak memory grows with the number of
orders the search returns. Since `order-reconciliation/07` that includes orders closed
since the last read-through, so the first read of a busy seller is the largest.

## To measure

Peak memory and wall time of a fetch at several sizes, using the per-run
`peak_memory_mb` the import logs. The sandbox returns fixed orders, so drive it with
faked SP-API responses of 100, 1,000 and 10,000 orders. Record memory per 1,000
orders, as `import-memory/01` did for Shopify.

## Options

Move Amazon onto the paged-source interface `import-memory/01` introduces, once
Shopify is on it. Amazon also closes Shipments at source and needs only identities
for that.

## Acceptance

- Memory per 1,000 Amazon orders is measured and recorded here.
- A read of 10,000 orders completes under `SHIPMENT_IMPORT_MEMORY_LIMIT`.
