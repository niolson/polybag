# Label batch throughput on one queue worker

Status: needs-triage
Category: performance
Created: 2026-10-24

## Problem

`BatchLabelService` dispatches one `GenerateLabelJob` per Package as a `Bus::batch`.
Memory per job does not grow with the batch, so this is the right shape. Throughput is
the open question.

`GenerateLabelJob` runs on `low`. The `queue` service runs one `queue:work` process
with `--queue=default,low`, which takes a job from `default` whenever there is one
before it takes the next `low` job. So:

- **A large batch's labels are bought one after another**, each waiting on its
  carrier. A batch takes about its size times one purchase's latency.
- **Work on `default` waits for at most one label job**, the one in flight, not for
  the whole batch.
- **Other `low` work waits for the whole batch**, because the worker takes `low` jobs
  in order. That is `ShadowValidateAddress` and `RebuildDailyShippingStats`. That is
  probably acceptable for both, but it should be confirmed.
- **A steady stream of `default` jobs delays the batch.** Every `default` job goes
  ahead of the next label.

A fatal error in one `GenerateLabelJob` leaves its Package neither bought nor failed
in the batch. That is [`import-memory/02`](../../import-memory/issues/02-a-queued-job-that-dies-says-so.md).

## To measure

- Wall time per label by carrier, against sandboxes and against fakes with realistic
  latency.
- Time to finish batches of 50, 200 and 500 Packages on one worker, with and without
  a steady load of `default` jobs, such as a tracking refresh running at the same time.
- Peak memory per `GenerateLabelJob`, including a Label whose response carries large
  customs documents.

## Options

1. **More `queue` worker processes**, as more replicas or more `queue:work` processes
   per container. Concurrency is bounded by carrier rate limits and by how an account
   behaves under concurrent purchases. `--max-jobs` only recycles a worker after N
   jobs; it adds no concurrency.
2. **Label batches on a queue of their own**, with their own worker. A batch then
   neither waits behind `default` nor holds up the rest of `low`.

## Acceptance

- Throughput is measured and recorded here.
- A 500-Package batch finishes in a stated time, and work on `default` and `low`
  keeps moving while it runs.
