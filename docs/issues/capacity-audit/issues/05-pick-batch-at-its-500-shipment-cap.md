# A pick batch at its 500-Shipment cap

Status: needs-triage
Category: performance
Created: 2026-10-24

## Problem

Generate Pick Batch allows up to 500 Shipments (`maxValue(500)`), and
`PickBatchService::autoGenerate()` loads them with `->limit($batchSize)->get()`. The
picking summary is rendered through Gotenberg in the web request and returned base64
encoded for the document printer (`ViewPickBatch`). A batch also has a pack slip run
(`PickBatchService::packSlipRun()`), which [04](04-pack-slip-run-renders-in-one-request.md)
covers.

Unlike pack slips, the summary aggregates items by product, so it should grow with
distinct SKUs more than with Shipments. That is the guess to check.

## To measure

For batches of 50, 200 and 500 Shipments, with few and with many distinct SKUs:

- peak memory and wall time of creating the batch;
- peak memory and wall time of rendering the summary;
- the summary PDF's size.

## Acceptance

- The numbers are recorded here.
- A 500-Shipment batch with many distinct SKUs creates and prints within the web
  memory limit and the request timeouts, or the cap is lowered with a message.
