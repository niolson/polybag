# Which Shopify price an order declares

Status: needs-triage
Category: bug
Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

`order-currency`. Blocked by `01`. Needs a probe on a development store before it can be
specified.

## Problem

The Shopify import values each item at `lineItem.originalUnitPriceSet.shopMoney.amount`
(`ShopifySource`, in the fulfillment order fragment and the item mapping). Two things about
that may be wrong for customs, which wants what the buyer actually paid:

1. **It is before discounts.** `originalUnitPriceSet` is the list price. A 30% discount
   code still declares the full price, overstating the value, the duties the recipient
   pays, and the value checked against IOSS and UK thresholds. Shopify also exposes a
   discounted price (`discountedUnitPriceAfterAllDiscountsSet` on `LineItem`, to be
   checked against the API version we use), which includes order-level discounts
   allocated to the line.
2. **It is in the shop's currency, not the buyer's.** With Shopify Markets a Canadian buyer
   on a US store pays in CAD (the presentment currency). `shopMoney` is that amount
   converted to USD at Shopify's rate at checkout; `presentmentMoney` is what the buyer paid.
   The transaction value is the presentment amount.

This matters only where PolyBag writes the customs declaration: a direct USPS, UPS or FedEx
Label for a Shopify order. A Label bought through Shopify Shipping is a blind purchase, and
Shopify fills in its own customs form.

## To find out

On a development store with a second market in another currency:

- Place an order with a line discount and an order-level discount code, paid in the other
  currency.
- Capture `originalUnitPriceSet`, `discountedUnitPriceSet` and
  `discountedUnitPriceAfterAllDiscountsSet`, each with `shopMoney` and `presentmentMoney`
  and their `currencyCode`.
- Check how a partly refunded or edited order reports them, since a fulfillment order can
  be imported again after an edit.
- Save the raw responses to `.scratch/order-currency/`.

Then decide:

- **Discount:** declare after all discounts, unless the probe shows a reason not to. A
  free item (discounted to zero) still needs a nominal customs value, which carriers
  refuse at zero.
- **Currency:** declare in the presentment currency, recording it as the Shipment's
  currency (`01`), unless the probe shows the presentment amounts are unreliable.

## Notes

- The Amazon import sums the `ITEM` proceeds breakdown, which should already be the amount
  after promotions (`ItemPromotionBreakdown` is a separate type). Confirm from a real
  discounted order rather than assume it.
- The Shipment total (`value`) and the item values must stay consistent; `ShopifySource`
  computes both from the same price today.
