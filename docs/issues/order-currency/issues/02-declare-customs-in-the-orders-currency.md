# Declare customs in the order's currency

Status: ready-for-agent
Category: bug
Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

`order-currency`. Blocked by `01`, which records the currency.

## Problem

Every customs declaration PolyBag sends says `USD`, whatever the order was paid in:

- **FedEx:** `commodities[].unitPrice.currency` and `customsValue.currency`
  (`FedexAdapter`)
- **UPS:** the international form's `CurrencyCode` and `InvoiceLineTotal.CurrencyCode`
  (`UpsAdapter`)
- **Amazon Shipping and Buy Shipping:** the package and item values
  (`AmazonBuyShippingService::packagePayload()`, `shippingItemsFor($package, 'USD')`,
  `offAmazonItemsFor(..., 'USD')`)
- **USPS:** `itemValue` / `itemTotalValue`, which carry no currency at all

Once `01` records a CAD order as CAD, sending those amounts as USD declares the wrong value.

Customs values a parcel at its transaction value: what the buyer paid, in the currency
they paid it. The destination's customs converts at its own official rate on the day of
import. Declaring in the order's currency is therefore the accurate answer and needs no
rate at all. A conversion is needed only where a carrier insists on one currency.

## Desired behavior

- **FedEx and UPS** declare each commodity, and the invoice total, in the Shipment's
  currency.
- **Amazon Shipping and Buy Shipping** send the Shipment's currency on package and item
  values, where the Shipping API accepts it. Where it accepts only the marketplace's
  currency, convert to that.
- **A carrier that takes only USD** gets the values converted at the Shipment's pinned
  `customs_rate_date` (`01`). Check USPS first: the Labels API's international customs
  form appears to be USD-only.
- **The Label's customs snapshot** records the currency declared and, when values were
  converted, the rate date and source currency. A reprint or a claim can then show what
  was sent.
- **Carriage declared value** (insurance) is not a customs value and stays in USD, as `01`
  computes it.

## Notes

- **FedEx has its own currency codes.** It does not use ISO 4217 throughout: GBP is `UKL`,
  MXN is `NMP`, CHF is `SFR`, JPY is `JYE`, among others. FedEx needs a mapping from ISO,
  checked against FedEx's currency code table, and a currency missing from it should
  convert to USD rather than fail the Label.
- **UPS** takes ISO codes, but check which currencies each destination's commercial invoice
  accepts.
- Shopify blind purchases are unaffected: Shopify makes its own customs form for those.
- `CustomsReadiness` messages that print a dollar total ("The customs total is $…") show
  the declared currency instead.

## Acceptance

- [ ] A FedEx international Label for a CAD Shipment declares CAD on every commodity
- [ ] A FedEx Label for an MXN Shipment sends FedEx's code for the peso
- [ ] A UPS international Label for a CAD Shipment declares CAD on the form and invoice

- [ ] A USPS international Label for a CAD Shipment declares the USD equivalent at the

- [ ] The Label's customs snapshot records the declared currency and, for a converted
      declaration, the rate date
- [ ] A USD Shipment's declarations are unchanged
