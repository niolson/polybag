# FedEx: `EU_DE_MINIMIS` regulatory details on every EU-bound commodity

Status: ready-for-agent
Category: enhancement
Repo: `polybag`

> *This was generated by AI during triage.*

## Parent

[PRD](../PRD.md). Needs `01`.

## Problem

`FedexAdapter::buildCustomsClearanceDetail()` sends name, description, origin, quantity,
value, weight and HS code per commodity and no `regulatoryDetails`. From 1 November 2026
FedEx makes the product identifiers mandatory on EU-bound B2C shipments and EU customs
holds anything without them.

## Desired behaviour

`AddressData` gains `isInEuropeanUnion()` — true for the EU27 country codes, nothing
else. It sits beside `isMilitary()` and `isUsTerritory()`.

When the destination is in the EU and the shipment carries a customs declaration, every
commodity gets one `regulatoryDetails` entry:

```json
{
  "regulationCode": "EU_DE_MINIMIS",
  "productId": "<merchantProductId>",
  "productIdType": "SKU",
  "details": {
    "merchantProductId": "<merchantProductId>",
    "nonStandardManufacturerProductId": "<manufacturerProductId>",
    "standardManufacturerProductId": "<standardProductId or the placeholder>"
  }
}
```

The placeholder for a missing standard identifier is `"NA"`, as the Ship API
documentation specifies — that is the API contract; the Compatible notice's `"NO"` is
a summary of the EU rule, not of the field. It is one constant on the adapter with a
comment naming both sources, and `05` confirms it with FedEx; if FedEx says otherwise
the constant changes and this ticket's comment records who said so.

A commodity is given a `regulatoryDetails` entry only when it has **both** a merchant
and a manufacturer identifier. `productId` is required by the schema and the
`details` object is meaningless without its two mandatory members, so a partial entry
is an invalid body, not a partial declaration. A commodity missing either is sent with
no `regulatoryDetails` at all — exactly today's body. `04` refuses such a shipment for
a consumer consignee; for a business consignee it is bought without identifiers, which
is the correct declaration for a shipment the rule does not apply to.

Non-EU destinations send exactly what they send today.

The rate request's placeholder `Merchandise` commodity
(`buildRateApiRequest()`, ~line 435) is left alone unless `05` finds the sandbox
rejecting it.

- [ ] `fedexShip.json` (`carrier-request-schema-validation/02`) extended with

      schema guard catches a misspelled key
- [ ] `FedexAdapterTest`: a shipment to Germany with all three identifiers sends the
      block above on each commodity; one with no `gtin` and a Code 128 barcode sends
      `"NA"`; one whose product has a SKU but no manufacturer part number sends no
      `regulatoryDetails` on that commodity and the full block on the others; one to
      Canada sends no `regulatoryDetails`
- [ ] `Log::channel('fedex-validation')` label request shows the block, so a sandbox
      run in `05` can be read back from the log

## Out of scope

- The €150 threshold. Identifiers are sent on every EU-bound line
- `CPSC` regulatory details
- Deciding who is a consumer — `04`
